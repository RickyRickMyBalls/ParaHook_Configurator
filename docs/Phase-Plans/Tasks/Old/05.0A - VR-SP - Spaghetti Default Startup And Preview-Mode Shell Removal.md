## Doc Body

### Summary

`5.0A` makes `spaghetti` the real default way the app opens.

This phase should:
- stop presenting `Legacy` versus `Spaghetti` as the main left-dock choice
- make the app land directly in `spaghetti`
- remove the `Preview Mode` card from the default left-dock stack
- remove the `Parts / Assembled` toggle with that card
- move `workerError` surfacing into the `Console`
- keep any remaining legacy code internal-only for one transition step

### Locked Outcome

At the end of `5.0A`:
- normal startup lands in `spaghetti`
- the user no longer sees the `Legacy / Spaghetti` branch chooser
- the `Preview Mode` card is gone from the left dock
- the `Parts / Assembled` toggle is gone with it
- worker/build errors still have a visible user-facing surface through the `Console`
- legacy code may still exist underneath, but it is no longer part of ordinary shell flow

### Locked Current-State Framing

Current shipped read:
- `useAppStore` still defaults `inputMode` to `'legacy'`
- `Toolbar` still owns:
  - the visible `Legacy / Spaghetti` chooser
  - the old `Parts / Assembled` toggle
  - the current `workerError` surface
- `ViewerHost` still branches rendering on `inputMode`
- `AppShell` still gates `BoxPanel` on `legacy`

Important implication:
- `Preview Mode` is not only decorative shell UI
- it is still the visible face of a real app branch

### Locked Startup Rule

Normal startup should always land in `spaghetti`.

Rules:
- do not preserve `legacy` as a normal startup destination
- if some temporary internal escape hatch is still needed during transition, it is not part of the product UI

Important rule:
- the startup default changes before the visible branch card is removed

### Locked `Preview Mode` Removal Rule

The visible `Preview Mode` card should leave the default left dock in `5.0A`.

Rules:
- remove the card entirely from ordinary left-dock rendering
- do not keep a mini version of the old `Legacy / Spaghetti` branch chooser
- do not preserve the card just because legacy code still exists internally

### Locked `Parts / Assembled` Rule

The old `Parts / Assembled` toggle should be removed with `Preview Mode`.

Rules:
- do not re-home it as another standalone shell control
- let `Browser` plus `Spaghetti Editor` own that workflow instead

Important rule:
- `5.0A` removes the old preview-branch panel instead of preserving leftover controls from it

### Locked `workerError` Rule

`workerError` should no longer depend on `Toolbar.tsx` once `Preview Mode` is removed.

Rules:
- move worker/build error surfacing to the `Console`
- do not replace the old preview card with a new permanent left-dock error banner in `5.0A`

Important rule:
- build/runtime errors should remain visible to the user
- they just should not depend on the old preview panel to be seen

### Locked Removal Order

Use this order:

1. change startup default to `spaghetti`
2. verify normal spaghetti-first startup flow works
3. remove the visible `Preview Mode` card and `Legacy / Spaghetti` chooser
4. remove the `Parts / Assembled` toggle with that card
5. route `workerError` to the `Console`
6. leave deeper hidden legacy-branch deletion deferred to `5.0C`

Why:
- hiding old UI and deleting old logic are different risk levels
- `5.0A` should complete the shell-facing cleanup without pretending the deeper code cleanup already happened

### Important Interfaces / Behavior To Lock

- `inputMode`
  - startup default becomes `spaghetti`
- `setInputMode`
  - removed from visible shell interaction
- `viewMode`
  - no longer driven by the old `Preview Mode` card
- `workerError`
  - no longer surfaced through `Toolbar.tsx`
  - surfaced through the `Console`
- `Preview Mode` card
  - removed from default left-dock rendering

### Non-Goals

Do not pull these into `5.0A`:
- `Parts List` cleanup
- `Box Params` cleanup
- full deletion of `legacy` input-mode code
- broader workspace hosting or pane layout work from `[5.1]`

### Acceptance And Done Shape

`5.0A` is done when:
- a fresh app launch lands in `spaghetti`
- there is no visible `Legacy / Spaghetti` chooser in ordinary shell flow
- the `Preview Mode` card no longer renders in the default left dock
- the `Parts / Assembled` toggle is gone with that card
- the main viewer still renders correctly on first launch
- the spaghetti/editor shell remains usable without touching a hidden branch
- worker/build error still has a visible user-facing surface through the `Console`
- any remaining legacy path is internal-only and no longer part of ordinary shell flow

### Verification Notes

- fresh app launch lands in `spaghetti`

Viewer verification:

- worker/build error still has a visible user-facing surface via `Console`
