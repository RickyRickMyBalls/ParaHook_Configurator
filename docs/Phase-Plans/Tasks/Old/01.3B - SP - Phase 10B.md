## Arch Spec

### Spec Target

This implementation target is only:
- `[1.3B] SP - Phase 10B - Graph-Local Preview And Build Memory`

This cut intentionally sits:
- after `10A`, which already made compile/build request/result routing graph-aware
- before `10C`, which will define graph output declaration / handoff semantics
- before later Browser hierarchy and project ownership work

If this cut is wrong, later work has no stable base for:
- graph-local accepted build-output ownership
- graph-local preview render-source ownership
- explicit viewer-target projection
- non-viewed graphs remaining built without sharing one singleton spaghetti bucket

### Problem Statement

After `10A`, the app now has:
- graph-aware compile/build request and result identity
- graph-local build request ordering truth
- graph-local `previewPreparation`
- graph-aware stale-drop rules

But it still does not have:
- graph-local ownership of accepted spaghetti build outputs
- graph-local preview render-source ownership
- explicit viewer-target state
- spaghetti inspection surfaces that follow viewer target instead of shared global build output

Current runtime still behaves too much like:
- `useAppStore.acceptBuildResult(...)` writes accepted spaghetti results into app-global `parts`
- `ViewerHost.tsx` resolves spaghetti preview rendering from focused editor viewport plus app-global `parts`
- `PartsListPanel.tsx` and `DebugInspectorDrawer.tsx` still read shared build-output state
- `bootstrapBuildWiring.ts` still reads spaghetti pending build data from one active-graph path

`10B` needs to remove those one-global preview/build-memory assumptions before `10C` defines the later output handoff surface.

### Locked Direction

- `10B` is the graph-local runtime-memory cut that comes after `10A` routing identity and before `10C` output handoff
- shared infrastructure stays shared:
  - one app shell
  - one worker lifecycle
  - one viewer shell
  - one Browser shell
- runtime truth stops being shared:
  - accepted spaghetti build outputs move out of app-global `useAppStore.parts` ownership for spaghetti mode
  - accepted spaghetti preview/build memory becomes graph-local in `useSpaghettiStore`
- the shared viewer must read from explicit viewer-target state:
  - `viewerTargetGraphDocumentId: string | null`
- viewer target is separate from build truth:
  - a graph may remain built while not currently viewed
  - focus may update viewer target by rule, but does not own build truth
- first-pass read-surface rule:
  - spaghetti inspection/read surfaces should follow `viewerTargetGraphDocumentId`
  - this includes `PartsListPanel` and the debug-preview read-model direction for spaghetti mode
- first-pass presentation-state rule:
  - spaghetti visibility/selection remains shared viewer-shell presentation state for now
  - `10B` moves runtime build/preview memory graph-local, not all viewer UI state

### Locked Runtime Contract

`10B` must add or formalize graph-local runtime ownership for:

```ts
type GraphRuntimeState = {
  compileBuild: GraphCompileBuildState
  previewPreparation: GraphPreviewPreparation
  acceptedBuildOutputs: PartArtifact[]
  acceptedPreviewBuildOutputs: PartArtifact[]
}
```

Working meaning:
- `acceptedBuildOutputs`
  - the graph-owned accepted spaghetti build artifacts for inspection and runtime truth
- `acceptedPreviewBuildOutputs`
  - the graph-owned build-output source currently used to derive preview render VM state
  - may alias `acceptedBuildOutputs` in the first pass if no narrower split is needed

`10B` must also add explicit shared-viewer target state:

```ts
viewerTargetGraphDocumentId: string | null
```

Rules:
- viewer target is presentation state, not build truth
- focus may update it through an explicit setter/update rule
- Browser/editor focus must not implicitly redefine runtime truth

Reused routing contracts from `10A`:
- `GraphBuildRequestEnvelope`
- `GraphBuildResultEnvelope`

Rules:
- `10B` reuses these contracts as-is
- `10B` must not add `assemblyId`, `objectId`, `partId`, or Browser-tree ids to the first-pass worker contract

### Current Seam Findings

#### `useAppStore.ts`

Current seam:
- spaghetti accepted build results still project into app-global `parts`
- `acceptBuildResult(...)` still bridges spaghetti results into global viewer/list state
- app-global `parts`, `partsVisibility`, and `selectedPartKey` still sit on the main viewer/list path

`10B` consequence:
- app-global `parts` stops being canonical spaghetti runtime truth
- accepted spaghetti build outputs must write into graph-local runtime state first
- app-global `parts` remains canonical only for legacy mode after `10B`
- shared visibility/selection may stay in `useAppStore` for first-pass `10B`

#### `ViewerHost.tsx`

Current seam:
- spaghetti preview rendering still follows focused editor viewport
- `selectPreviewRenderVmFromPreparation(...)` still consumes app-global `parts`

`10B` consequence:
- spaghetti preview rendering must follow explicit viewer-target state
- the render source must come from graph-local accepted build outputs
- focused editor viewport may update viewer target by rule, but cannot remain the implicit runtime owner

#### `bootstrapBuildWiring.ts`

Current seam:
- spaghetti providers still read pending build state from `selectActiveGraphPendingBuildState(...)`
- build results still flow back through `useAppStore.acceptBuildResult(...)`

`10B` consequence:
- pending build state may remain active-graph keyed for the request-launch path in first pass
- accepted runtime writes must stop depending on one active-graph read path
- the wiring layer remains the bridge from shared dispatch to graph-local runtime buckets

#### `useSpaghettiStore.ts`

Current seam:
- graph runtime already owns `compileBuild` and `previewPreparation`
- graph runtime does not yet own accepted spaghetti build outputs
- graph runtime does not yet own explicit viewer-target state

`10B` consequence:
- add graph-local accepted build-output ownership
- add explicit viewer-target ownership
- keep graph-local runtime truth in `useSpaghettiStore` rather than promoting it upward into `useAppStore`

#### `PartsListPanel.tsx` and `DebugInspectorDrawer.tsx`

Current seam:
- spaghetti inspection surfaces still read app-global build outputs

`10B` consequence:
- these surfaces should follow `viewerTargetGraphDocumentId` in spaghetti mode
- their spaghetti read models should resolve build outputs from the viewer-target graph runtime bundle
- first-pass visibility/selection stays shared even when the read-model source changes

### Implementation Sequence

1. Add graph-local accepted spaghetti build-output ownership to `GraphRuntimeState`.
2. Add `viewerTargetGraphDocumentId` to the canonical spaghetti/viewer coordination state.
3. Update `acceptBuildResult(...)` so spaghetti accepted results write graph-local runtime truth first, not app-global singleton spaghetti buckets.
4. Move spaghetti preview render-source selection to graph-local runtime plus explicit viewer target.
5. Update `ViewerHost` so spaghetti render selection follows explicit viewer target rather than focused editor as implicit truth.
6. Update spaghetti read surfaces to follow viewer target for first-pass `10B`.
7. Keep visibility/selection shared as presentation state for now.
8. Leave `10C` output declaration/handoff semantics out of the implementation.

### Acceptance Criteria

`10B` counts as done only when:
- accepted spaghetti build outputs are graph-local runtime truth
- preview-preparation / preview render-source data are graph-local runtime truth

- the shared viewer resolves spaghetti render source through `viewerTargetGraphDocumentId`
