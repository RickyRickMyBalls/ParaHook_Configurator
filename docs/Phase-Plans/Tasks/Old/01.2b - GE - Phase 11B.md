## Arch Spec

### Spec Target

This implementation target is only:
- `[1.2B] GE - Phase 11B - Cached Graph Lifecycle`

This cut is intentionally narrow:
- define Browser-owned cached graph entries
- layer cached entries on top of the existing live graph-document store
- define dirty/saved lifecycle rules for those cached entries
- define Browser reopen/focus behavior for cached graphs
- keep editor open/swap/import decisions out of the phase

If this cut is wrong, later work has no stable base for:
- `11C` editor save/load coordination
- `GE 12` project-level graph collection ownership
- Browser graph lifecycle beyond one purely in-memory session

### Problem Statement

After `11A`, the app now has:
- a durable `GraphDocument` file contract
- pure graph-document serialization/parsing helpers
- low-level browser file save/load services

But it still does not have:
- a Browser-owned cached graph entry model
- explicit saved graph versus cached live graph rules
- dirty/saved lifecycle rules for loaded or in-memory graph documents
- a lifecycle model for loaded graphs that survives beyond one immediate file-open action

Current runtime still behaves too much like:
- Browser and editor are looking straight at live graph documents
- saved files are only raw IO, not Browser-managed cached entries
- there is no explicit cached graph layer between file IO and editor interaction policy

`11B` needs to make cached graph lifecycle real before `11C` starts deciding how save/load actions affect editors.

### Locked Direction

- `11B` owns Browser-side cached graph lifecycle
- `11B` builds on the shipped `11A` persistence seam
- cached entries wrap existing live graph documents instead of replacing graph-document truth
- every live graph document gets a cached entry in the first pass
- cached graph rows are `open-or-focus` rows in the Browser
- graph identity and cached-entry identity remain explicit, but in first pass they use the same id value

### First-Pass Cached Lifecycle Direction

Use this first-pass direction:

```ts
type CachedGraphEntry = {
  cachedGraphId: string
  graphDocumentId: string
  source: 'in-memory' | 'file-load'
  isDirty: boolean
  lastSavedAt?: string
}
```

Rules:
- one cached entry wraps exactly one live graph document
- `graphDocumentsById` remains the live graph-authoring truth
- cached entries are Browser lifecycle objects layered alongside graph documents
- Browser rows should read from cached entries, then resolve display data through `graphDocumentId`
- runtime buckets and viewport state are not persisted into the cached entry itself
- first-pass `cachedGraphId === graphDocumentId`
- separate cached-entry identity is deferred until a later phase actually needs it

### First-Pass Store Additions

Use this first-pass conceptual store model:

```ts
cachedGraphEntriesById: Record<string, CachedGraphEntry>
cachedGraphEntryOrder: string[]
```

Rules:
- these records live beside:
  - `graphDocumentsById`
  - `graphDocumentOrder`
  - `editorViewportsById`
- `11B` does not replace the graph-document store
- `11B` does not introduce a project-level collection layer
- Browser graph rows should stop enumerating graph documents directly once cached entries exist

### First-Pass Lifecycle Rules

- every live graph document gets a cached entry in `11B`
- the startup/default graph document gets a cached entry
- `New Graph` creates a cached entry immediately
- `Duplicate Focused` creates a cached entry immediately
- file-loaded graph documents create cached entries immediately
- `source = 'in-memory'` for:
  - startup/default graphs
  - newly created graphs
  - duplicated graphs
- `source = 'file-load'` for graphs loaded from disk

### Dirty / Saved Rules

- startup/default in-memory graphs start dirty
- newly created in-memory graphs start dirty
- duplicated in-memory graphs start dirty
- file-loaded graphs start clean after successful load
- any committed graph-document edit marks that cached entry dirty
- successful save clears dirty and updates `lastSavedAt`
- dirty/saved state is event-driven in first pass, not deep content-diff driven
- raw runtime buckets are not dirty-state truth

### Browser Row Behavior In `11B`

- clicking a cached-graph row is `open-or-focus`
- if a viewport for that graph already exists, focus it
- otherwise open that graph using the existing `openGraphDocumentInViewport` behavior
- this is Browser lifecycle behavior, not `11C` editor-policy work
- `11B` does not introduce `Open In New Editor`, `Swap Current Editor`, or `Load Into New Graph`

### Locked Saved Versus Cached-Live Rules

- a saved graph file is durable file data
- a live graph document is the authored runtime truth in memory
- a cached graph entry is the Browser-owned lifecycle record around that live graph document
- cached entries may become dirty after editing
- dirty/live lifecycle rules belong here in `11B`
- how a cached entry is opened into a specific editor viewport beyond `open-or-focus` belongs later in `11C`

### 11B Store Placement

- `useSpaghettiStore` owns cached entries in first-pass `11B`
- Browser currently reads directly from graph documents
- `11B` inserts a cached-entry layer without replacing graph-document truth
- `GE 12` still owns later project-level graph collection ownership

# Close Out notes

What landed cleanly:
- wrapping the existing `graphDocumentsById` store was stable enough for the first `11B` cut
- `useSpaghettiStore` was the right first-pass home for cached entries
- Browser graph rows could move to cached-entry-backed rendering without changing the existing `openGraphDocumentInViewport` behavior

What mattered most:
- the useful lifecycle split was not "saved file versus editor" yet; it was:
  - durable graph file
  - live graph document
  - Browser-owned cached entry
- keeping `cachedGraphId === graphDocumentId` was enough for first pass and avoided an unnecessary extra identity layer

Behavior notes:
- startup/default, new, and duplicated in-memory graphs now start dirty
- file-loaded graphs start clean
- committed graph edits mark the cached entry dirty
- save clears dirty and records `lastSavedAt`

Carry-forward notes:
- `11C` should own `Open In New Editor`, `Swap Current Editor`, and `Load Into New Graph`
- `11C` should also decide whether later load/import actions preserve identity or intentionally clone into a new graph identity
- `GE 12` should own any later project-level cached graph collection above the current Browser/store layer
