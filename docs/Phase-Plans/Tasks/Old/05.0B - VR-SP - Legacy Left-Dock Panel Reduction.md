## Doc Body

### Summary

`5.0B` clears the rest of the obvious left-dock clutter after `5.0A`.

This phase should:
- remove `Parts List` from the left dock
- remove `Box Params` from the left dock
- preserve any still-needed behavior only as underlying state or code, without a temporary replacement surface
- make `Browser` read as the primary left-dock surface again

### Locked Outcome

At the end of `5.0B`:
- the left dock is no longer carrying `Parts List` or `Box Params`
- `Browser` is the only major always-visible general-purpose left-dock surface besides the optional docked `Spaghetti` meatball host
- any still-needed spaghetti-side visibility/selection behavior survives only as underlying state, not as a temporary replacement panel
- panel-file deletion is still deferred to later `5.0D`

### Locked Current-State Framing

Current shipped read:
- `AppShell` still mounts `PartsListPanel` in the default left-dock stack
- `AppShell` only hides `BoxPanel` indirectly because `inputMode` now defaults to `spaghetti`
- `PartsListPanel` still mixes two concerns:
  - legacy build-policy and instance-management controls
  - spaghetti-side output visibility and selection UI
- `BoxPanel` still exists as a legacy left-dock slider surface even though ordinary startup no longer needs it

### Locked Shell Removal Rules

#### `Parts List`

`Parts List` must be removed from the default left-dock mount path in `AppShell`, not merely hidden.

Important rules:
- `5.0B` does not need to finalize the long-range home for spaghetti output visibility/selection
- `5.0B` does need to stop mounting the old card in the default shell
- no Browser-adjacent fallback, mini inspector, or replacement card is introduced in this phase

#### `Box Params`

`Box Params` must be removed from normal user shell flow in `5.0B`.

Important rules:
- do not preserve it as a large always-open card just because a small amount of behavior still depends on it
- do not add a visible replacement drawer, mini inspector, or temporary panel in this phase
- if some legacy param behavior still matters before `5.0C`, it may survive only as underlying store/runtime behavior, not as ordinary shell UI

### Locked Implementation Rule

`5.0B` is a shell-subtraction phase first.

Implementation rule:
- remove panel mounting from the `AppShell` left-dock composition
- update related tests and mocks so they reflect the new default shell
- do not delete `PartsListPanel.tsx` or `BoxPanel.tsx` yet
- full dead-file, stale-style, and residue cleanup belongs later in `5.0D`

### Locked Behavior Preservation Rule

The only behavior that may intentionally survive `5.0B` is underlying non-shell behavior.

Locked preservation rules:
- `Parts List` UI does not survive as a temporary surface
- spaghetti-side visibility/selection state may remain alive underneath until a later real owner is chosen
- legacy build-policy and add/remove-instance controls do not block panel removal
- `Box Params` does not survive as a normal user-facing surface in any form during this phase

### Non-Goals

`5.0B` does not:
- merge `Parts List` into `Browser`
- introduce a temporary output inspector
- delete the `legacy` branch from `useAppStore`
- delete dead panel files
- reevaluate `parts` versus `assembled`
- absorb workspace-mode work from `[5.1]`

### Acceptance And Done Shape

`5.0B` is done when:
- `Parts List` is gone from the default left-dock stack
- `Box Params` is gone from the default left-dock stack
- `Browser` reads as the primary left-dock surface again
- no new fallback card, drawer, or mini inspector replaces the removed panels
- any still-needed spaghetti-side visibility/selection behavior survives only as underlying state, not as a temporary shell surface

Recommended proof bar:
- `AppShell` no longer mounts `PartsListPanel` in the default left-dock stack
- `AppShell` no longer exposes `BoxPanel` in the ordinary spaghetti-first shell flow
- `Browser` remains visible as the main left-dock surface
- no user-facing fallback card was added that recreates the same left-dock clutter under a different name
- test coverage is updated to reflect the new left-dock composition
- existing spaghetti-first startup behavior from `5.0A` remains intact after the panel subtraction
