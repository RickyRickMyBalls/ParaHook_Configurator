### Purpose

This file is the implementation-ready execution spec for the first reference transform-controls phase.

Use it to:
- define how reference transform mode is entered
- lock the first floating transform-toolbar shape
- define what transform state belongs in workspace truth
- keep reference transform tooling separate from import/file-format work and from later richer reference controls

Do not use it to:
- redesign the `References` Browser placement
- add new import formats
- add project persistence for imported references
- turn references into editable project-owned content

### Locked Product Rules
#### Fold Hack 4

#### `2.4D.R1` - Transform mode entry

Locked answer:
- the user enters reference transform mode by right-clicking a reference item row
- the menu action is `Transform Object`
- category rows do not expose this action
- there is no inline transform affordance on the row in `2.4D`

#### `2.4D.R2` - Hidden-reference behavior

Locked answer:
- if the user targets a hidden reference, the app turns that reference on
- if it is not yet loaded, the app ensures it is loaded first
- then transform mode begins on that reference

#### `2.4D.R3` - Toolbar shape

Locked answer:
- the first transform UI is a floating reference-only toolbar
- it is not the current `View` toolbar
- it contains:
  - `Move`
  - `Rotate`
  - `Scale`
  - `Local / World`
  - `Reset Transform`
  - `Close`

#### `2.4D.R4` - Gizmo ownership

Locked answer:
- reference transform mode temporarily owns the existing viewer gizmo engine
- while active, normal part gizmo attachment is suspended
- only one reference can be transformed at a time

#### `2.4D.R5` - Exit behavior

Locked answer:
- there is no `Apply` / `Cancel` flow in `2.4D`
- closing the toolbar exits transform mode and keeps the current transform
- pressing `Esc` exits transform mode and keeps the current transform
- `Reset Transform` is the only first-pass revert action

#### `2.4D.R6` - Default transform meaning

Locked answer:
- built-in references reset back to their manifest/default transform
- imported references reset back to their import-time neutral/default transform

#### `2.4D.R7` - Session persistence

Locked answer:
- transform overrides persist for the current workspace session
- they do not persist after reload
- they are not saved into project/file state in `2.4D`

#### `2.4D.R8` - Shared transform system

Locked answer:
- built-in references and imported references use the same transform pipeline
- `2.4D` does not create separate transform systems for those two reference sources

#### `2.4D.R9` - Camera behavior

Locked answer:
- entering transform mode does not auto-frame the reference
- the camera stays where it is unless the user frames manually later

### Important Interfaces And Types
#### Fold Hack 4

Reference workspace state should gain:
- active transform target reference id
- active transform mode:
  - `move`
  - `rotate`
  - `scale`
- active transform space:
  - `local`
  - `world`
- per-reference transform override:
  - position
  - rotation
  - scale

Browser row/context surface should gain:
- `Transform Object` for reference item rows only

Viewer/reference bridge should gain explicit reference-transform support:
- attach gizmo to a reference object
- detach from reference transform mode
- switch mode and local/world space
- apply and read back reference transform overrides
- restore a reference to its default base transform

Runtime cleanup rule:
- if the active reference is hidden, removed, or unloaded, transform mode exits automatically
