### Purpose

This file is the implementation-ready execution spec for:
- `[2.4C] VR - User Reference Import From Disk`

Use it to:
- implement the first user-facing disk-import workflow for reference models
- keep imported references as workspace/viewer context, not project-owned content
- lock the first Browser/viewer behavior for imported reference rows

## Spec Target

Ship the first user-imported reference flow on top of the existing `02.4A` and `02.4B` reference workspace:
- import through the `Content` section `+` button
- support exactly `.step`, `.stl`, `.obj`, `.glb`
- surface imported files under `References > User References`
- keep imports workspace-only with no reload persistence
- keep imported-row controls minimal and direct

## Problem Statement

`02.4A` and `02.4B` ship built-in reference libraries and `.step` support, but users still cannot bring their own viewer-context files into the workspace.

`02.4C` closes that gap without turning imported references into project-owned content, asset-library infrastructure, or richer viewer-edit tools.

The implementation must:
- reuse the current reference workspace/viewer path where possible
- keep the Browser clean
- avoid introducing a second persistence system
- avoid dragging transform/edit tooling from later `[2.4D]` into this first import cut

## Locked First-Pass Rules

### Browser And UX

- The only first-pass import entrypoint is a small `+` button on the top right of the `Content` box.
- That `+` button opens the import menu.
- The import menu contains exactly:
  - `Import .step`
  - `Import .stl`
  - `Import .obj`
  - `Import .glb`
- Imported references live under `References` in a dedicated child category named `User References`.
- Imported references do not merge into `Footpads`, `Shoes`, or `Premade Foothooks`.
- Imported row face is:
  - filename as the main label
  - a small file-type tag as row meta: `STEP`, `STL`, `OBJ`, `GLB`
- Row click keeps the same meaning as built-in reference rows:
  - toggle visibility on/off in the viewer

### Ownership And Persistence

- Imported references are workspace-only in `[2.4C]`.
- Imported references do not survive reload.
- Imported references do not write into project/app persistence in this phase.
- Imported references are viewer/workspace context only and do not become published project `Content`.

### File Scope

- `[2.4C]` supports only:
  - `.step`
  - `.stl`
  - `.obj`
  - `.glb`
- No other file types are added in this phase.
- The first pass stays restricted to already-supported viewer loaders.

### Duplicate, Error, Retry, And Remove Behavior

- Duplicate imports are allowed.
- When the same file is imported twice:
  - keep both rows
  - auto-disambiguate visible names, for example:
    - `shoe.glb`
    - `shoe.glb (2)`
- Failed imports stay visible in the Browser.
- Failed rows show `Error`.
- Failed rows stay retryable in place.
- Remove is a true workspace removal/unload, not a hide-only action.
- Imported rows do not use a default `...` menu in `[2.4C]`.
- Imported row inline actions are:
  - retry icon button only when errored
  - `X` remove button always
- The retry icon sits to the left of the `X`.

### Import Flow

- Each import action imports one file at a time, not multi-select.
- On successful import:
  - create the imported row
  - place it under `References > User References`
  - turn it on immediately in the viewer
  - begin load immediately
- Retry reuses the same imported record and source URL.
- Retry does not create a duplicate row.

## Important Interfaces And State

### Reference Workspace State

Extend the current `ReferenceWorkspaceState` so it can hold imported-reference records separately from the static manifest entries.

Each imported reference record must include at minimum:
- generated `referenceId`
- visible label
- file type
- workspace-only blob/object URL
- `isVisible`
- `loadState`
- `errorMessage`

### Browser Tree Read Model

Extend the Browser reference tree so it produces:
- existing built-in categories unchanged
- a dynamic `User References` category under `References`
- imported item rows that follow the same visibility-state bar model as built-in reference rows

Imported rows should surface:
- filename label
- file-type meta tag
- inline retry button when errored
- inline `X` button for remove

### Viewer / Loader Integration

Imported files should reuse the current format-specific viewer load branches where possible.

Use workspace-only blob/object URLs so imported files can flow through the same loader code paths used by:
- `.glb`
- `.obj`
- `.stl`
- `.step`

Object URLs must be revoked when:
- the imported row is removed
- the workspace state is torn down

## Implementation Order

1. Extend reference workspace state for imported records, per-item visibility/load/error truth, and the dynamic `User References` category.
2. Add the `Content` header `+` action and the import menu for the four accepted formats.
3. Add the single-file import path that creates imported records from local files using object URLs.
4. Merge imported rows into the Browser tree under `References > User References`.
5. Add imported-row inline actions:
  - retry when errored
  - `X` remove always
6. Reuse the current viewer loader path so imported rows load, show, hide, retry, and unload correctly.

## Deferred / Out Of Scope

Do not add any of this in `[2.4C]`:
- persistence across reload
- project-managed asset libraries
- folder scanning
- transform/edit tools for imported refs
- richer context menus as the default row action model
- materials tooling
- selection/editability systems that blur imported refs into project-owned content
- broader file-type expansion beyond `.step`, `.stl`, `.obj`, `.glb`

Those belong later, especially:
- `[2.4D]` reference transform controls
- later richer viewer/reference control work

## Acceptance / Proof Bar

`[2.4C]` is complete when all of the following are true:

- The `Content` box shows a small top-right `+` button that opens the import menu.
- The import menu offers exactly `.step`, `.stl`, `.obj`, and `.glb`.
- Imported files appear only under `References > User References`.
- Imported rows show filename plus a small file-type tag.
- Imported rows turn on immediately after successful import and begin loading right away.
- Imported row click toggles visibility on/off after import.
- Duplicate imports are allowed and visible names are disambiguated.
- Failed imports remain visible as `Error` rows.
- Errored rows can retry in place without creating duplicates.
- Imported rows expose a direct `X` remove button.
- Removing an imported row truly unloads/removes it from the current workspace session.
- Reloading the app does not restore imported rows.
- Built-in reference categories and built-in manifest references behave exactly as before.
