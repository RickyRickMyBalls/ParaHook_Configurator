## Doc Body

### Summary

Ship the first honest app-wide `Console` as a bottom-docked shell owned by `AppShell`, with one collapsed bottom row and one expanded upward panel sharing the same transcript store.

The first cut should be useful immediately for debugging and command visibility, while still staying narrower than full command routing.

It should include:
- one collapsed bottom console row
- one expanded resizable bottom-docked console panel
- one shared transcript store and VM behind both modes
- one real visible input field with explicit-focus behavior
- visible layered messages for the required first-pass feedback channels

### Locked Outcome

`4.1A` is locked as:
- one app-wide console owned by `AppShell`
- one collapsed bottom row plus one expanded bottom-docked panel
- one shared transcript store and VM
- explicit-focus real input field
- narrow typed command behavior only
- session-only transcript history
- simple per-layer toggles and clear action
- no floating/undocking and no full command-router migration yet

### Shell And UX Behavior

- the collapsed console row always lives at the bottom of the app shell / viewport region
- the collapsed row always shows:
  - the visible input field
  - the current prompt or latest-line summary
  - a dedicated expand/collapse button
- the expanded console opens upward from that same row, not as a separate tool
- the expanded console is bottom-docked only in `4.1A`
- the expanded console resizes vertically only, by dragging its top edge
- the expanded console shows:
  - transcript history
  - simple layer toggles
  - a clear action
  - the same shared input seam at the bottom of the panel
- collapsed and expanded console modes are two views of the same stateful system, not two separate products

### Input And Typed Command Behavior

- the input field is real and focusable in `4.1A`
- freeform typing only enters the console when the user explicitly focuses or clicks the console input
- `4.1A` does not globally capture arbitrary printable keys
- `Enter` submits typed input
- typed command support in `4.1A` is intentionally narrow:
  - `help`
  - `console`
  - command echo lines
  - friendly unknown-command feedback
- reserved immediate tool shortcuts like `M / R / S / X / Y / Z` are not re-routed through full console ownership in `4.1A`
- instead, existing feature areas may publish command/shortcut transcript lines into the console without forcing a full shortcut migration yet
- text input guards remain strict:
  - `input`
  - `textarea`
  - `select`
  - contenteditable surfaces
  keep keyboard ownership when focused

### Required First-Pass Layers

- `Commands`
- `Shortcuts`
- `App`
- `Worker`
- `Diagnostics`
- `Params`
- `Selection`

### Transcript Model

- both console modes read from one shared app-level transcript/state source
- transcript entries are chronological
- transcript entries carry at minimum:
  - `id`
  - timestamp or monotonic sequence
  - `layer`
  - short `text`
  - optional `source`
  - optional `severity`
- transcript history is session-only in memory for `4.1A`
- transcript history does not persist across reload
- the expanded panel `Clear` action clears the current-session transcript only
- layer visibility is controlled by simple per-layer toggles
- layer toggles filter what is shown, but do not destroy stored entries

### Important Interfaces And Types

- add `ConsoleLayer` for the first required layer set
- add `ConsoleSeverity` for normal / info / warn / error style message levels
- add `ConsoleTranscriptEntry` with:
  - `id`
  - timestamp or monotonic sequence
  - `layer`
  - `text`
  - optional `source`
  - optional `severity`
- add app-level console state for:
  - `isExpanded`
  - `expandedHeight`
  - `inputText`
  - `entries`
  - `visibleLayers`
- add minimal console actions for:
  - append transcript entry
  - clear transcript
  - set input text
  - toggle expanded state
  - set expanded height
  - toggle visible layer
  - submit typed input

### First-Pass Integration Targets

`4.1A` should publish obvious existing signals into the transcript without forcing a full command-ownership rewrite.

First-pass publishers should include:
- app/build notes
- worker/build progress notes
- diagnostics and error notes
- selection changes
- parameter or value-change notes where already easy to surface
- shortcut notes from the current reference-transform flow

Important rule:
- `4.1A` should make the console useful immediately for debugging active behavior
- `4.1A` should not expand into a full system-wide shortcut migration just to make those first lines appear

### Locked Deferrals

Keep these out of `4.1A` if they threaten the shell/transcript core:

- full typed command execution model
- rich command parsing and aliases
- autocomplete or fuzzy command search
- global router ownership of all shortcuts
- user hotkey rebinding UI
- advanced per-layer inspector controls
- replacing the existing structured debug inspector
- floating or undockable console variants

Those belong in later `4.1B+` follow-ups.

### Test Plan

- `AppShell` renders a persistent bottom console row in normal shell layouts
- the row expand button opens the shared bottom-docked console panel
- collapsing the panel returns to the same bottom row
- expanded console resize keeps a sane min and max height within the shell
- collapsed row and expanded panel read from the same transcript store
- layer toggles hide and show transcript lines without destroying stored history
- transcript clear removes current-session lines only
- the input field accepts typing only when focused
- the console does not steal typing from normal text-editing fields
- `Enter` on `help` yields the expected help transcript feedback
- `Enter` on `console` yields the expected console command feedback
- unknown typed commands yield friendly feedback instead of silent failure
- first transcript publishers can append:
  - `Commands`
  - `Shortcuts`
  - `App`
  - `Worker`
  - `Diagnostics`
  - `Params`
  - `Selection`
- the existing `Debug Inspector` remains unchanged
