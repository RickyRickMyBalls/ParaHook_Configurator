## Arch Spec

### Spec Target

This implementation target is only:
- `[1.3C] SP - Phase 10C - Graph Output Handoff Surface`

This cut intentionally sits:
- after `10A`, which already made compile/build request and result routing graph-aware
- after `10B`, which already made accepted preview/build runtime memory graph-local and viewer-target-driven

### Problem Statement

After `10B`, the app now has:
- graph-local accepted build-output ownership
- graph-local preview-preparation ownership
- explicit viewer-target state
- viewer/render selection that no longer depends on one global spaghetti parts bucket

But it still does not have:
- one graph-owned output declaration / handoff object per graph
- one canonical source for current publication meaning
- current output-facing selectors that read the same graph-owned published output seam

Current runtime still behaves too much like:
- `previewPreparation.ts` carries implicit publication meaning
- `selectPartsListItems.ts` reconstructs slot state directly from graph topology plus diagnostics
- `selectDebugInspectorVm.ts` rebuilds `OutputPreview` meaning ad hoc from graph topology plus build outputs
- preview render selectors and viewer consumers read a different path from the parts/debug surfaces

`10C` needs to stop that split-brain output story by introducing one graph-owned output surface that current output-facing readers can consume directly.

### Locked Direction

- `OutputPreview` node params remain the authored declaration source of truth
- `10C` adds a derived graph-owned published output surface above that authored truth
- the first-pass output surface is graph-scoped, not Browser-scoped
- the first-pass output surface is minimal and slot-oriented:
  - no `assemblyId`
  - no `objectId`
  - no `partId`
- all declared slots publish into the output surface:
  - `empty`
  - `unresolved`
  - `resolved`
- the graph-owned output surface is the canonical handoff seam for current output-facing readers
- viewer/render logic remains a consumer and does not become the owner of graph publication truth
- later `AS` and `GE - Phase 12` work owns richer output organization and project composition

### Locked Output Contract

Use one graph-owned output-surface object per graph document.

```ts
type GraphOutputSurface = {
  graphDocumentId: string
  publishedAtBuildSeq: number | null
  surfaceVersion: number
  entries: GraphPublishedOutputEntry[]
}

type GraphPublishedOutputEntry = {
  outputEntryId: string
  slotId: string
  sourceNodeId: string
  label: string
  state: 'empty' | 'unresolved' | 'resolved'
  acceptedArtifactKey: string | null
  diagnosticsState?: 'none' | 'hasDiagnostics' | 'unknown'
}
```

Rules:
- one `GraphOutputSurface` exists per graph document
- `surfaceVersion` is the first-pass schema/version marker for this handoff surface, not authored declaration revision history
- `acceptedArtifactKey` stays a minimal artifact identity token in first pass
- `diagnosticsState` stays optional and lightweight in first pass

Important rule:
- this is the first graph-owned output handoff surface
- it is not the final long-term Browser/project output model

### Locked Authored-Versus-Published Rule

`OutputPreview` node params remain the authored declaration source of truth.

`GraphOutputSurface` is derived from:
- authored `OutputPreview` slot declarations
- accepted graph-local build outputs
- current slot diagnostics / readiness state

Rules:
- authored declaration intent stays on the graph/node side
- published output truth lives in the graph-owned derived output surface
- `10C` must not replace authored `OutputPreview` truth with an opaque runtime-only structure
- derived output truth may be recomputed store-side in first pass rather than stored as persisted authored data

Plain-English rule:
- `OutputPreview` says what the graph wants to publish
- `GraphOutputSurface` says what is currently published from that declaration

### Locked Identity And Slot-State Rule

Each published output entry must carry slot-scoped graph output identity.

Required identity:
- `outputEntryId`
- `slotId`
- `sourceNodeId`

Optional but useful:
- `acceptedArtifactKey`

Identity rules:
- `outputEntryId` should be graph-output-entry-scoped, derived from graph + source node + slot identity rather than accepted artifact identity alone
- entry identity must stay stable even when a slot is unresolved or temporarily empty
- `10C` must not invent later hierarchy ids

Required states:
- `empty`
- `unresolved`
- `resolved`

State rules:
- `empty`
  - slot is declared but has no bound/resolved output yet
- `unresolved`
  - slot is declared and intended, but current accepted runtime/build state cannot resolve it
- `resolved`
  - slot is declared and currently maps to accepted graph-local output

Working rule:
- publish all declared slots, not only resolved ones

### Implementation Sequence

1. Add `GraphOutputSurface` ownership to `GraphRuntimeState` in `useSpaghettiStore`.
2. Add derivation/update logic that recomputes the output surface from:
   - authored `OutputPreview` slots
   - accepted graph-local build outputs
   - current slot diagnostics/readiness
3. Expose selectors for:
   - graph output surface by `graphDocumentId`
   - viewer-target graph output surface
4. Reroute current spaghetti output-facing readers to the new surface:
   - parts-list read models first
   - debug/output inspection read models next
5. Keep preview-render/viewer logic separate:
   - preview render VM may consume the new output surface or compatible source data
   - viewer presentation does not become publication truth
6. Leave Browser hierarchy, project composition, and richer output structure deferred.

Implementation note:
- first-pass derivation may happen store-side rather than as a persisted authored field
- this is acceptable as long as authored declaration truth remains on the graph/node side and the published output surface becomes the canonical graph-owned handoff seam

### Acceptance Criteria

`10C` counts as done only when:
- each graph owns a stable graph-owned output surface
- authored `OutputPreview` truth remains separate from derived published output truth
- all declared slots publish as output entries even before full resolution
- `empty`, `unresolved`, and `resolved` states are represented explicitly
- accepted runtime/build changes update only the correct graph output surface
- current output-facing spaghetti readers can consume the graph-owned output surface directly
- viewer-target changes do not redefine graph publication truth
- stale and wrong-graph writes cannot overwrite another graph's output surface
- no first-pass dependency on `assemblyId`, `objectId`, or `partId` exists

This phase is not allowed to claim:
- full Browser/project hierarchy
- final Browser-facing output structure
- project ownership/composition rules
- final output packaging/export semantics

Required task-doc acceptance note:
- `10C` is complete only when one canonical graph-owned output handoff seam exists and current spaghetti output-facing readers no longer need to reconstruct publication meaning ad hoc
