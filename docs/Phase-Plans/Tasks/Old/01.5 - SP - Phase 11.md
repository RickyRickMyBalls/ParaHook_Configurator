### Problem Statement

The Browser already had:
- project content rows
- graph open/save actions
- open viewport rows

But it still behaved too much like:
- a graph launcher
- a flat graph list
- a Browser that did not visibly show graph-owned publication

`SP - Phase 11` needed to make the Browser into a real hierarchy tree without prematurely collapsing graph publication, project content, and later Browser workspace controls into one surface.

### Locked Direction

- the first pass should establish `Project -> Graph Documents` as a real Browser branch
- graph rows should be expandable
- expanded graph rows should show one thin graph-owned child-output level
- graph-row child content should read from graph-owned publication truth, not project-owned placement
- the Browser should clearly reflect graph open/focused state
- the phase should stop before deeper project-content or Browser workspace systems

### Locked First-Pass Browser Structure

The shipped first-pass Browser structure is:
- `Project`
  - `Content`
  - `Graph Documents`
    - `Graph A`
      - `Published Output 1`
      - `Published Output 2`
  - `Open Viewports`

Working rule:
- graph documents get the first honest hierarchy branch
- one thin published-output level proves the tree
- later project-content and output-structure phases can deepen the Browser from here

### Locked First Child-Row Unit

The first child-row unit under graph rows is:
- published graph output rows

Those rows represent:
- `GraphPublishedOutputEntry`

Those rows are derived from:
- `GraphOutputSurface.entries`

Do not treat them as:
- project-owned component rows
- object rows
- part rows

### Locked Browser Truth Boundary

Graph rows and published graph output rows read from:
- `useSpaghettiStore`

Specifically:
- cached graph entry state for saved/dirty lifecycle
- graph-document identity/name
- graph runtime `outputSurface`
- editor viewport focus/open state

Browser expand/collapse remains:
- local Browser/workspace UI state

Project content remains:
- a separate `useAppStore` seam

Plain-English rule:
- graph rows come from the graph store
- project rows come from the project store

### Current Seam Findings

`BrowserPanel.tsx`
- already owned the Browser section layout and graph actions
- needed a real graph-tree view model instead of a flat graph list

`useSpaghettiStore.ts`
- already owned the graph-document, cached-entry, output-surface, and editor-viewport state needed for graph rows
- did not need new ownership rules for this phase

`useAppStore.ts`
- already owned the separate project-content branch
- should remain separate from graph-row child truth in this phase
