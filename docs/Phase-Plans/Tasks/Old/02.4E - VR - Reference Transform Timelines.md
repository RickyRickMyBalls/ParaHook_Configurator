### Summary
#### Fold Hack 4

`2.4E` is the next possible follow-up after the shipped reference transform toolbar.

Simple read:
- `2.4D` shipped manual transform controls for references
- `2.4E` would let individual transform values animate over time

The core idea is:
- right-click a value row in the reference transform toolbar
- choose `Basic` or `Timeline`
- if `Timeline` is selected, that value gets its own expanded boxed animation area

Likely first covered values:
- `Move X`
- `Move Y`
- `Move Z`
- `Rotate X`
- `Rotate Y`
- `Rotate Z`
- `Scale X`
- `Scale Y`
- `Scale Z`
- `Rotate Snap`

### Locked Inputs So Far
#### Fold Hack 4

#### `2.4E.R1` - Entry rule

Current locked direction:
- the user right-clicks a value row in the transform toolbar
- the context menu exposes:
  - `Basic`
  - `Timeline`

#### `2.4E.R2` - Basic mode meaning

Current locked direction:
- `Basic` means the currently shipped direct/manual value control
- choosing `Basic` removes or hides the extra timeline area for that value

#### `2.4E.R3` - Timeline mode meaning

Current locked direction:
- `Timeline` means the value is no longer only a static manual number
- the value gains a timeline section directly under the main row
- the row and timeline area should read as one boxed control group

#### `2.4E.R4` - First timeline controls

Current locked direction:
- a `Speed` slider should be present
- it should reuse the existing slider template language already used in the transform toolbar
- a graph/editor area should let the user draw how the value moves back and forth

#### `2.4E.R5` - First graph-edit direction

Current locked direction:
- the graph should support adding points
- the user should be able to move points
- the user should be able to adjust curve character
- likely first curve shapes include:
  - linear
  - curved
  - ramped
  - down

#### `2.4E.R6` - First cycle controls

Current locked direction:
- a dropdown should define how time cycles
- the first expected modes are:
  - `Left to Right`
  - `Bounce`
  - `Right to Left`

### Questions Still Needed
#### Fold Hack 4

#### `2.4E.Q1` - Runtime ownership

Still needs decision:
- do timeline values evaluate only while the transform toolbar is open
- or do they become persistent workspace animation state for that reference value during the session

Suggested answer:
- make timeline values persistent workspace-session state
- closing the toolbar should not erase the timeline behavior

#### `2.4E.Q2` - Evaluation scope

Still needs decision:
- should multiple timeline-enabled values run at once on the same reference
- or should `2.4E` only allow one animated value at a time first

Suggested answer:
- allow multiple timeline-enabled values on the same reference
- keep the model per-value instead of forcing one global animated channel

#### `2.4E.Q3` - Basic/manual interaction while timeline is active

Still needs decision:
- when a value is in `Timeline` mode, does the top value row become the base value, the live preview value, or a readout only

Suggested answer:
- keep the top row as the base value/control
- timeline output modulates from that base rather than replacing the row entirely

#### `2.4E.Q4` - Playback trigger

Still needs decision:
- do timelines always run immediately once enabled
- or does the toolbar need a per-value or global play/pause state

Suggested answer:
- first pass should auto-run when `Timeline` is enabled
- avoid adding a full transport system in `2.4E`

#### `2.4E.Q5` - Graph editing depth

Still needs decision:
- how much curve editing is needed in the first pass

Suggested answer:
- support point add/move/remove and real curve-handle control in the first pass
- let the user directly shape the curve between points instead of only choosing from a fixed preset list
- keep simple interpolation presets as helpers, not as the only curve-edit path
- do not build a full DCC-grade curve editor in `2.4E`
