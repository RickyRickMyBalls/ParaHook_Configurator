## Arch Spec

### Spec Target

This implementation target is only:
- `[2.4B] VR - Expanded Reference File Support`

This cut intentionally sits:
- after the shipped `02.4A` static-manifest reference workspace
- before `02.4C` user import from disk
- before later richer Browser/viewer reference controls in `[2.5]`

Plain-English rule:
- keep the same `References` workspace, but make `.step` references real

### Problem Statement

`02.4A` shipped the first usable reference workspace, but it still leaves `Premade Foothooks` as a placeholder because the current hook assets are `.step`.

Without `02.4B`, the Browser/reference system still has a visible category that cannot become real using the current file-support surface.

`02.4B` needs to:
- keep the static-manifest model from `02.4A`
- add browser-side STEP import/tessellation
- populate `Premade Foothooks` using the existing hook files
- present `.step` load failures honestly without hiding broken rows

### Reasonable Phase Cut

`02.4B` should stay small enough to ship as one clear follow-up to `02.4A`.

This phase should actually do:
- add `.step` to the supported reference file types
- add a browser-side STEP importer using `occt-import-js`
- tessellate STEP assets into viewer mesh data inside the current reference load flow
- manifest all current hook assets under `Premade Foothooks`
- keep failed STEP rows visible with retryable error state

This phase should not try to solve:
- user import from disk
- broader new file-type expansion beyond `.step`
- reference worker offloading
- richer material/edit tools

### Locked File-Type Scope Rule

The first expanded file-support cut is:
- keep existing `.obj`
- keep existing `.glb`
- keep existing `.stl`
- add `.step`

Do not add any other new file types in `02.4B`.

Plain-English rule:
- `02.4B` is the `.step` phase, not the “support everything” phase

### Locked Source Model Rule

Keep the source model unchanged from `02.4A`:
- static checked-in manifest remains the only source of truth

Do not add:
- runtime folder scanning
- ad hoc file discovery
- user import

Manifest responsibilities still include:
- display label
- category id
- exact public asset path
- file type
- optional display transform

### Locked `Premade Foothooks` Rule

`Premade Foothooks` becomes fully real in this phase.

Manifest these current hook assets:
- `large.step`
- `medium.step`
- `small.step`
- `xl.step`

Browser result:
- `Premade Foothooks` is no longer a placeholder-only category after `02.4B`
- all four current hook rows appear under that category

### Locked STEP Implementation Rule

Use:
- `occt-import-js`

Implementation rule:
- import STEP in-browser
- tessellate STEP into mesh data
- convert that mesh data into the same viewer-side cached reference object model used by existing reference items
- keep the first cut in the current async viewer-side reference loading path

Do not introduce:
- a custom worker-only STEP architecture
- a second independent reference pipeline

### Locked Browser And Error-State Rule

Reference item row meaning stays the same:
- click row = toggle one item on/off
- `+/-` remains expand/collapse only

New error rule:
- failed reference rows stay visible in the Browser tree
- failed item state label = `Error`
- clicking the same errored row again retries loading

Category aggregate state:
- `Loading` if any visible child is loading
- `Error` if no child is loading and any child is errored
- `On` if any child is visible and loaded
- `Off` otherwise

Plain-English rule:
- broken STEP rows stay visible and retryable instead of silently disappearing

### Locked Visibility And Cache Rule

Keep the `02.4A` visibility rules:
- references start hidden by default on app load
- first toggle-on triggers load
- toggle-off hides but does not unload
- second toggle-on of an already loaded item reuses the cached mesh

Apply the same rule to `.step` items.

### Important Interfaces And Types

Lock these additions:
- `ReferenceFileType`
  - extend to include `'step'`
- `ReferenceManifestItem`
  - keeps current fields from `02.4A`
  - keeps optional `displayTransform`
- reference load-state model remains:
  - `'unloaded'`
  - `'loading'`
  - `'loaded'`
  - `'error'`

Viewer integration additions:
- add a STEP branch in `Viewer.ensureReferenceLoaded(...)`
- add a STEP import/tessellation helper using `occt-import-js`
- convert imported STEP geometry into the same cached `Object3D` / `Mesh` path used for existing references

Browser read-model rule:
- `.step` rows still use ordinary `reference-item` rows
- row meta should read as `STEP`

5. Tighten Browser state labels and retry behavior for error rows.
6. Add targeted tests for `.step` manifest rows, load-state transitions, retry behavior, and category-state aggregation.

## Acceptance / Proof Bar

Manifest and Browser acceptance:
- `Premade Foothooks` contains:
  - `large.step`
  - `medium.step`
  - `small.step`
  - `xl.step`
- `.step` rows render as normal reference rows with `STEP` meta
- Browser placement inside `Content > References` stays unchanged

Loader/state acceptance:
- visible STEP item transitions `unloaded -> loading -> loaded`
- failed STEP item transitions to `error`
- clicking an errored row retries and can recover to `loaded`
- already loaded STEP item toggles on/off without re-importing

Category acceptance:
- clicking the `Premade Foothooks` category row toggles all current hook items on/off
- category state shows:
  - `Loading` when any visible child is loading
  - `Error` when none are loading and any child is errored
  - `On` when any child is visible and loaded
  - `Off` otherwise

Regression acceptance:
- existing `Footpads` and `Shoes` behavior remains unchanged
- `02.4A` Browser placement and toggle semantics remain unchanged
