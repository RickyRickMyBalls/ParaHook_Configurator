- the earlier geometry-type and sketch-shell work framed in `[3.2A]`

Working scope rule:
- `[3.2C]` should make the first profile-to-solid step real without trying to complete the wider solid-feature library or re-litigate the `Sketch` architecture that `[3.2A]` and `[3.2B]` already locked

## Arch Spec

### Spec Target

This implementation target is only:
- `[3.2C] SP / NI / FS / GE - Extrude Foundation`

This cut intentionally sits:
- after the first usable `Sketch` contract and profile flow from `[3.2A]` and `[3.2B]`
- before the next profile-based body step in `[3.2D]`

### Required Substrate From `[3.2A]` And `[3.2B]`

This phase assumes the following are already the accepted product/runtime substrate:
- `Geometry/Sketch` is the first-class graph-native sketch node
- `Geometry/Sketch` already publishes:
  - `out:SketchProfiles`
  - `out:SketchProfile`
- profile detection and profile selection stay user-facing inside `Sketch`
- the floating draw/review workflow belongs to `Sketch`, not `Extrude`

Substrate rule:
- `3.2C` must extend the shipped graph-native geometry path, not route users back through the old feature-stack-first sketch/extrude workflow

### Problem Statement

ParaHook's foundational geometry lane now has a clearer sketch-side direction, but the graph still lacks the first honest profile-to-solid node that would make that geometry path meaningful.

Without this cut:
- the first geometry-authoring slice stops at profile planning
- the graph cannot yet prove `Sketch -> SolidBody`
- later loft and feature growth have no stable first body-feature baseline

### Locked First-Pass Win

`[3.2C]` counts as real when:
- `Extrude` exists as a real user-facing node
- one selected sketch profile can produce one `SolidBody`
- the first `Extrude` surface stays small and mode-based instead of leaking helper internals
- the first contract remains honest to the runtime instead of overpromising unimplemented behavior

Plain-English rule:
- make one honest profile-to-solid step real before chasing the broader solid-feature library

### Locked Graph-Native Ownership Model

The primary user-facing host for `[3.2C]` is:
- `Geometry/Extrude`

Product ownership rule:
- the graph-native user-facing path is:
  - `Geometry/Sketch -> Geometry/Extrude -> SolidBody`
- old feature-stack extrude seams remain compatibility/runtime substrate only
- `ExtrudeFeatureView`, feature-stack store methods, and feature virtual ports must not define the public product contract for this phase

### Locked Extrude Type And Mode Boundary

The public `ExtrudeType` enum for the first contract should contain:
- `Basic`
- `Twist`

First implementation behavior:
- `Basic` is the only executable mode
- `Twist` is part of the public enum but explicitly disabled/deferred in the first implementation

Mode rule:
- the first shipped node surface may show `Twist` as a visible-but-disabled future mode
- it must not behave as an active executable path until runtime support exists

### Locked Public `Geometry/Extrude` Contract

The first honest graph-native `Extrude` contract is:
- one selected profile input:
  - `in:ExtrusionProfile - [SketchProfile]`
- one depth input row:
  - `in:Depth - [FloatMm]`
- one mode selector:
  - `in:ExtrudeType - [Enum]`
- one `out:SolidBody - [SolidBody]`

Implementation shape to lock:
- `Geometry/Extrude` is a dedicated node type under the `Geometry/*` family
- it should use its own node template path rather than reusing the `part` or old feature-stack shell
- `ExtrudeType` is stored in node params and rendered as a local mode selector in the first pass
- `Depth` is a true number input row with a local fallback param value
- `ExtrusionProfile` is a required graph input; there is no local profile-source picker in the new node

Stable identity rule:
- keep `bodyId` as the stable identity seam for the resulting solid body
- keep helper wire/face/runtime artifacts internal

### Locked Profile Input Model

`Geometry/Extrude` should consume one selected downstream-ready profile from `Geometry/Sketch`.

Compatibility rule:
- preserve the existing internal `closeProfile -> profileRef -> extrude` path under the hood
- keep profile selection user-facing inside `Sketch`
- do not broaden the first public contract to support multiple equal profile-source models

Implementation rule:
- the public product language is:
  - `Geometry/Sketch -> Geometry/Extrude`
- the first public `Geometry/Extrude` node does not expose:
  - source feature picker
  - profile picker
  - mixed sketch/closeProfile public source models
- the compile/lowering path may still convert the upstream selected profile into the existing internal `profileRef` substrate where needed

### Locked `SolidBody` Output And Failure Contract

The public `SolidBody` contract for the first graph-native node is:
- evaluator/VM-level success shape:
  - `{ bodyId: string }`
- evaluator/VM-level failure shape:
  - `null`

Failure rule:
- invalid extrude publishes no `SolidBody`
- diagnostics stay attached to the node
- the viewer/build preview must not keep stale body output when the current extrude fails

Compatibility rule:
- `evaluateGraph.ts` already accepts `solidBody` values as `{ bodyId }`, `null`, or opaque-ref tokens
- the first public graph-native node should use `{ bodyId }` or `null` as its stable evaluator-facing contract
- lower-level opaque refs may remain internal if later runtime plumbing needs them

### Locked Runtime Truth Boundary

The doc must stay honest to the current runtime and what `[3.2C]` must change.

Current runtime truth:
- current worker execution honestly supports positive-depth extrusion only
- current worker runtime still extrudes along global `+Z`
- current feature-stack UI/schema already carry `taper` and `offset`, but they are not part of the first honest public graph-native contract

`[3.2C]` runtime upgrade requirement:
- graph-native extrusion must follow the selected sketch plane normal for:
  - `XY`
  - `XZ`
  - `YZ`
- global-`+Z` coercion is not honest enough for this phase

Plane-source rule:
- the current `SketchProfile` payload does not carry plane metadata
- `3.2C` should not expand the public `SketchProfile` payload just to solve this
- instead, graph-native lowering in `compileGraph.ts` should resolve the upstream `Geometry/Sketch` source node from the incoming `ExtrusionProfile` edge and read the effective sketch plane there

Runtime honesty rule:
- if the runtime does not execute a parameter in a meaningful way, that parameter does not belong in the first public contract

Compatibility rule:
- existing `taper` and `offset` fields may remain in legacy/schema compatibility seams if needed for old feature-stack data
- they are not part of the first public graph-native contract or proof target

### Locked Preview / Build Visibility Boundary

`Geometry/Extrude` must be visible in the graph/runtime preview path, not only valid as an inert evaluator token.

Implementation rule:
- `3.2C` must extend the current compile/preview mapping beyond part-feature stacks so graph-native `Geometry/Extrude` nodes can participate in body preview
- the minimum honest rule is:
  - each `Geometry/Extrude` node that compiles successfully contributes one previewable body
  - that body can be resolved by node identity into the existing preview/render path

Compatibility/default rule:
- if the current preview pipeline still expects part-key-based mapping, `3.2C` must add the smallest deterministic graph-native body mapping needed for `Geometry/Extrude`
- do not defer preview/body visibility to a later undocumented follow-up

### Locked Viewer / Node Surface

`Geometry/Extrude` is a node-side editor surface in the first pass, not a viewer-mode tool family.

First-pass node surface should expose:
- `ExtrudeType`
- selected profile summary/source node
- depth control
- one resulting body summary

First-pass node surface should not expose:
- viewer gizmos for body creation
- viewer-side edit mode comparable to the sketch draw/review tools
- profile source pickers
- profile choice pickers
- twist controls as active inputs while twist is still deferred
- taper controls
- offset controls
- direction controls
- start/origin controls

Viewer rule:
- the viewport may preview the resulting body
- the viewport is not the primary edit surface for `Extrude` in `[3.2C]`

## Implementation Order

1. Add `Geometry/Extrude` node type, default params, and port contract in the graph-native registry/schema path.
2. Define evaluator-facing `SolidBody` success/null behavior and selector VM shape for the new node.
3. Build graph-native lowering from incoming selected `SketchProfile` into runtime extrude IR.
4. Resolve the upstream sketch plane from the source `Geometry/Sketch` node during lowering rather than expanding the public `SketchProfile` payload.
5. Upgrade runtime extrusion so `XY`, `XZ`, and `YZ` all extrude along the selected sketch plane normal.
6. Extend preview/body mapping so graph-native `Geometry/Extrude` bodies can render in the viewer/output preview path.
7. Add the graph-native node UI surface with `Basic` plus disabled `Twist`, selected profile summary, depth, and one body summary.
8. Verify failure behavior, output parity, preview visibility, and compatibility with the old internal `profileRef` substrate.

## Acceptance Criteria

- `Geometry/Extrude` exists as a real user-facing node
- one selected profile extrudes into one solid body
- positive finite depth succeeds
- zero or negative depth is rejected safely
- `ExtrudeType.Basic` executes
- `ExtrudeType.Twist` is present in the public enum but disabled/deferred in the first implementation
- one `SolidBody` output remains the only public result surface
- public profile input is only selected `SketchProfile` from `Geometry/Sketch`
- extrusion follows the selected sketch plane normal for `XY`, `XZ`, and `YZ`
- invalid extrude publishes no `SolidBody` and leaves diagnostics on the node
- resulting body is previewable in the viewer/build-preview path
- old `closeProfile -> profileRef -> extrude` substrate still resolves correctly underneath where compatibility requires it
- the first public node surface does not overpromise taper/offset/direction/origin behavior
- graph-native schema/evaluator/runtime/preview seams stay aligned with the locked contract
