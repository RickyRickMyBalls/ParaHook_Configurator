## Arch Spec

### Spec Target

This implementation target is only:
- `[3.2C] SP / NI / FS / GE - Extrude Foundation`

This cut intentionally sits:
- after the first usable `Sketch` contract and profile flow from `[3.2A]` and `[3.2B]`
- before the next profile-based body step in `[3.2D]`

### Problem Statement

ParaHook's foundational geometry lane now has a clearer sketch-side direction, but the graph still lacks the first honest profile-to-solid node that would make that geometry path meaningful.

Without this cut:
- the first geometry-authoring slice stops at profile planning
- the graph cannot yet prove `Sketch -> SolidBody`
- later loft and feature growth have no stable first body-feature baseline

### Locked First-Pass Win

`[3.2C]` counts as real when:
- `Extrude` exists as a real user-facing node
- one selected sketch profile can produce one `SolidBody`
- the first `Extrude` surface stays small and mode-based instead of leaking helper internals
- the first contract remains honest to the runtime instead of overpromising unimplemented behavior

Plain-English rule:
- make one honest profile-to-solid step real before chasing the broader solid-feature library

### Locked Extrude Type And Mode Boundary

The public `ExtrudeType` enum for the first contract should contain:
- `Basic`
- `Twist`

First implementation behavior:
- `Basic` is the only executable mode
- `Twist` is part of the public enum but explicitly disabled/deferred in the first implementation

Mode rule:
- the first shipped node surface may show `Twist` as a visible-but-disabled future mode
- it must not behave as an active executable path until runtime support exists

### Locked First Honest Extrude Contract

The first honest `Extrude` node contract is:
- one selected profile input
- one positive finite depth input
- one `out:SolidBody - [SolidBody]`

The first user-facing contract explicitly defers:
- direction controls
- origin/start controls
- user-facing taper behavior
- user-facing offset behavior

Stable identity rule:
- keep `bodyId` as the stable identity seam for the resulting solid body
- keep helper wire/face/runtime artifacts internal

### Locked Profile Input Model

`Extrude` should consume one selected downstream-ready profile.

Compatibility rule:
- preserve the existing internal `closeProfile -> profileRef -> extrude` path under the hood
- keep profile selection user-facing inside `Sketch`
- do not broaden the first public contract to support multiple equal profile-source models

Implementation rule:
- the public product language is still `Sketch -> Extrude`
- the existing internal compatibility seam remains the first implementation substrate

### Locked Viewer / Node Surface

`Extrude` is a node-side editor surface in the first pass, not a viewer-mode tool family.

First-pass node surface should expose:
- `ExtrudeType`
- selected profile summary/source
- depth control
- one resulting body summary

First-pass node surface should not expose:
- viewer gizmos for body creation
- viewer-side edit mode comparable to the sketch draw/review tools
- twist controls as active inputs while twist is still deferred

Viewer rule:
- the viewport may preview the resulting body
- the viewport is not the primary edit surface for `Extrude` in `[3.2C]`

### Locked Runtime Truth Boundary

The doc must stay honest to the current runtime:
- current worker execution honestly supports positive depth extrusion only
- current UI/schema may already carry `taper` and `offset`, but they are not part of the first honest shipped contract
- `Twist` exists in the enum but is disabled/deferred until runtime support lands

Runtime honesty rule:
- if the runtime does not execute a parameter in a meaningful way, that parameter does not belong in the first public contract

Compatibility rule:
- existing optional `taper` and `offset` fields may remain in compatibility seams if needed for legacy/schema stability
- they are not part of the first user-facing contract or proof target

## Implementation Order

1. Lock the public `ExtrudeType` contract to `Basic` plus disabled `Twist`.
2. Reduce the first user-facing node surface to selected profile plus positive depth.
3. Preserve the internal `closeProfile -> profileRef -> extrude` compatibility seam while keeping the user-facing flow integrated behind `Sketch`.
4. Align feature types and schema with the first honest contract and any required compatibility fields.
5. Align compile/IR lowering so the runtime receives only the behavior the contract actually promises.
6. Align the worker runtime around one-profile one-body positive-depth extrusion as the first proof target.
7. Align virtual-port behavior so the first public contract does not drift from the UI/runtime contract.
8. Add or update tests proving success/failure behavior and parity across UI/schema/IR/runtime.

- existing `closeProfile -> profileRef -> extrude` flow still resolves correctly
- the first public node surface does not overpromise taper/offset/direction/origin behavior
- virtual-port and schema parity stay aligned with the locked first contract
