### Locked First-Pass Persistence Rule

The first pass should remember one last hybrid workspace state.

Persist:
- tiled layout tree
- pane assignments
- tiled versus windowed surface placements
- floating rects for windowed surfaces
- active pane identity

Do not require in first pass:
- named saved layout libraries
- task-specific workspace presets
- project-authored workspace content

### Locked Persistence Ownership Rule

Workspace layout persistence should be treated as user/workspace preference state, not project-authored content.

Important rule:
- do not store workspace layout as part of authored project/build data

Recommended home:
- shared workspace store under `src/app/workspace/`
- persisted through the same general preference direction used for other app-level UI state

### Locked Saved-Mode Extension Rule

Named saved workspace modes belong here as the later extension of the same persistence model.

First-pass rule:
- only remember the last layout

Later follow-up:
- save named workspace modes
- restore named workspace modes
- optionally support task-oriented layout presets

### Locked Migration Rule

The current Spaghetti-specific split/meatball shell should be treated as the first migration source, not as a permanent parallel system.

Migration checkpoints:
- keep the current left-dock split toggle as the first tiled-entry seam
- move split-tree ownership out of `useSpaghettiStore`
- move shared layout ownership near `AppShell`
- migrate `Spaghetti Editor` into the shared hosted-surface model
- migrate `Console` and other eligible surfaces into the same shared owner

Important rule:
- do not keep one old Spaghetti-only split renderer plus one new general workspace renderer long-term

### Locked Deprecation Boundary

The old special-case `AppShell` split path should be deprecated only after the shared workspace owner can replace its user-facing behavior.

Replacement requirements before deprecation:
- shared tile-tree exists
- shared title-bar/divider split authoring exists
- shared tiled/windowed transition model exists
- `Spaghetti Editor` and left-dock entry behavior both work through the shared system

### Important Interfaces And Types To Lock

- `PersistedWorkspaceLayout`
  - root tile tree
  - pane assignments
  - tiled/windowed placement map
  - active pane id
- `FloatingSurfaceRectMap`
  - floating geometry keyed by surface instance id
- `SavedWorkspaceMode`
  - named later extension of persisted workspace layout
- migration checkpoints
  - `AppShell` handoff
  - `useSpaghettiStore` split/meatball handoff
  - left-dock split-toggle reuse

### Acceptance And Done Shape

`5.1D` is done when:
- first-pass persisted workspace state is explicit
- persistence is clearly user/workspace preference state
- saved named modes have a clear later home
- migration checkpoints from current shell seams are explicit
- the deprecation boundary for the old special-case split renderer is explicit
