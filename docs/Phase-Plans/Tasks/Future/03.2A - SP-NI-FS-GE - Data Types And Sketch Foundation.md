### Locked First `Inputs` Row Shape

The `Inputs` section should start as explicit rows, not a loose parameter block:

```text
Sketch
└─ Inputs
   └─ SketchPlane row
      ├─ input pin: [Plane]
      ├─ label: SketchPlane
      ├─ value: empty or assigned plane
      └─ action: +  (start plane pick)
```

First input-row behavior:
- the row keeps a normal graph input pin so an upstream plane can be wired into it from the canvas
- the row-level `+` is the primary first-pass way to assign the sketch plane
- if a plane is already wired into the input pin, that wired plane is the authoritative assignment
- clicking `+` should collapse/minimize the broader spaghetti editor
- the viewer should enter plane-pick mode for this sketch
- the first options shown in the viewer should be ghost preview planes/grids around the origin for:
  - `XY`
  - `XZ`
  - `YZ`
- choosing one of those previews assigns `SketchPlane` and returns the user to the normal `Sketch` node/editor state

Deferred from this first row flow:
- clicking arbitrary planar faces
- custom offset/work planes
- richer plane history/management UI

## Locked Answers

### 1. Immediate First-Class Types Vs Deferred Types

Lock first-class now:
- `[Float]`
- `[Boolean]`
- `[Enum]`
- `[Vec2]`
- `[Plane]`
- `[SketchProfiles]`
- `[SketchProfile]`
- `[SolidBody]`

Defer or keep thin in `[3.2A]`:
- `[Vec3]`
- `[Transform2D]`
- `[SketchCurve]`
- `[SketchCurveRef]`

Conditional only if cheap and honest:
- `[SketchCurves]`

Reason:
- the current graph/runtime already has real primitive transport for numbers, booleans, and `vec2`
- the current feature path already treats plane, profile output, and solid-body output as real seams
- `Transform2D`, explicit curve objects, and curve refs are not yet graph-native contracts the current code honestly depends on

### 2. First Honest `Sketch` Shell Pins

Lock the first shipped shell as:
- `in:SketchPlane - [Plane]`
- `out:SketchProfiles - [SketchProfiles]`
- `out:SketchProfile - [SketchProfile]`

Optional in the same cut only if it can be surfaced honestly:
- `out:SketchCurves - [SketchCurves]`

Explicitly defer from the shell:
- `in:SketchPlace - [Transform2D]`

Rule:
- ship the smallest shell that can feed downstream `Extrude` work without forcing speculative placement or curve-reference contracts

Locked input-row rule:
- `SketchPlane` should render as its own neat row under `Inputs`
- that row should keep its normal graph input pin
- its right-side `+` action should be the first entrypoint into plane assignment
- the row must support both assignment paths:
  - wired upstream plane via the input pin
  - direct local plane pick via the `+` action
- the first assignment flow should show only `XY`, `XZ`, and `YZ` ghost plane/grid previews around the origin
- arbitrary face-picked plane creation should stay deferred for a later pass

Locked hierarchy rule:
- the first shipped `Sketch` node should already read as:
  - `Inputs`
  - `Draw/Edit Curves Inside`
  - `Close/Select Profile`
  - `Outputs`
- but in `[3.2A]`, only `Inputs`, `Outputs`, and the empty internal authoring surface are required to exist honestly

### 3. `SketchCurve` Vs `SketchCurveRef`

Lock this first-pass modeling rule:
- do not make both `SketchCurve` and `SketchCurveRef` first-class in `[3.2A]`
- keep authored sketch geometry internal to the sketch/feature component layer in this phase
- expose resolved profiles first because that is the honest downstream seam already used by extrusion
- if a curve-facing output is needed in the first pass, prefer `SketchCurves` before introducing `SketchCurveRef`
