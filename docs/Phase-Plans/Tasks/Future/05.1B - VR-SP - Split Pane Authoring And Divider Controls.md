### Locked First-Split Entry Rule

Standalone floating tool surfaces should be able to create the first split from their own title bars.

Right-click actions:
- `Split Horizontal`
- `Split Vertical`

Rules:
- this applies while the surface is `Windowed`
- the split always anchors against the current `Model Viewer` region
- choosing the action creates the requested split and moves that surface into the new pane

Plain-English rule:
- floating standalone tools split off the model viewport first

### Locked Divider Authoring Rule

Once a split exists, deeper subdivision should come from divider lines.

Divider right-click menu should own:
- `Split Horizontal`
- `Split Vertical`
- `Close Split`
- `Merge With Neighbor`
- row/column priority actions

Important rule:
- do not keep adding one-off per-surface secondary split logic once the divider already represents the layout structure

### Locked Divider Resize Rule

Dividers should support:
- drag to resize
- right-click for layout actions
- double-click to reset the local ratio to a balanced default

Recommended default:
- double-click resets the local branch ratio to `0.5`

### Locked Priority Model

Each branch owns:
- current ratio
- priority mode

First priority modes:
- `balanced`
- `favor first`
- `favor second`

Plain-English read:
- ratio = where the bar is now
- priority = who keeps more authority later when the workspace resizes or another split is inserted

### Locked Minimum-Size Policy

Every tiled surface type should have minimum width and height constraints.

Rules:
- respect minimums before allowing a divider to move farther
- clamp divider movement instead of allowing unusable slivers
- prefer internal pane scrolling before impossible layout states

Important rule:
- minimum-size policy belongs to the workspace system, even if values vary by surface type

### Locked Close And Merge Rule

If a pane is removed:
- the remaining sibling should absorb the space
- the parent split should collapse away when only one child remains

Rules:
- `Close Split` should remove the targeted pane branch when valid
- `Merge With Neighbor` should collapse two adjacent regions into one surviving pane
- the only viewer-protection rule from `5.1A` still applies:
  - do not allow the workspace to delete the only main viewer region accidentally
