## Doc Body

### Summary

Extend the shipped `4.1A` console shell so one shared console system can present in three modes:

- `Docked`
  - the current bottom-docked main-shell console
- `Floating`
  - a movable, resizable in-app console window
- `Pop-Out`
  - a dedicated browser window that hosts the console full-screen

`4.1B` must preserve the current docked console as the default main-shell mode while adding the two new window modes without splitting the console into separate products.

### Locked Outcome

`4.1B` is locked as:
- one shared console system with three presentation modes:
  - `Docked`
  - `Floating`
  - `Pop-Out`
- separate console header controls for `Float` and `Pop-Out`
- `Docked` remains the default main-shell mode
- `Floating` is a movable, resizable in-app window with restored fillets
- `Pop-Out` is a dedicated browser window using the docked/full-window shell with no fillets
- when `Pop-Out` is open, the child window is the only owner of the expanded console
- the main app keeps only the collapsed bottom row while popped out
- closing the pop-out returns the main app to collapsed-row-only mode

### Mode Model

#### `Docked`

- uses the existing `4.1A` docked shell behavior
- remains attached to the bottom of the main app shell
- uses hard edges and no corner fillets
- remains the default mode when the console first opens in the main app shell

#### `Floating`

- lives inside the current app shell as a true floating window
- can be dragged by its header
- can be resized from any edge or corner like the reference transform toolbar
- stays clamped to the visible viewport bounds
- restores rounded corners/fillets and floating-window shadow treatment
- remembers its last floating rectangle for the current session:
  - `x`
  - `y`
  - `width`
  - `height`
- re-entering floating mode restores the last floating rectangle instead of resetting every time

#### `Pop-Out`

- opens in a separate browser window
- renders the console inside that new window as a full-window docked shell
- uses no corner fillets
- shares the same live transcript/state surface as the main app console
- becomes the only owner of the expanded console while the child window is open

### Main Mode-Switch UX

- mode switching belongs in console chrome, not in the tools menu
- `4.1B` uses separate header controls for:
  - `Float`
  - `Pop-Out`
- the docked return path may reuse:
  - the existing close/back-to-main behavior
  - or a dedicated `Docked` control
  but the implementation must still preserve the locked mode model above
- mode-switch controls are part of window management, not part of later command-routing work

### Shared State And Ownership Rules

- all three modes share one canonical console transcript/state system
- there is only one canonical console transcript/store
- there is only one expanded-console owner at a time
- transcript entries, visible layers, tool settings, and input state remain part of the same console system across mode switches

When switching modes:
- leaving `Floating` for `Docked` or `Pop-Out` preserves transcript and tools state
- leaving `Docked` for `Floating` or `Pop-Out` preserves transcript and tools state
- opening `Pop-Out` transfers expanded-console ownership to the child window

### Pop-Out Ownership And Close Rules

While `Pop-Out` is open:
- the pop-out window is the only owner of the expanded console
- the main app does not show a second expanded console at the same time
- the main app keeps the collapsed bottom row visible

If the user closes the pop-out browser window:
- the main-shell console returns to collapsed-row-only mode
- it does not auto-reopen the expanded docked console
- transcript and console state remain intact

### Styling Rules

- `Docked`
  - hard-edged shell
  - no fillets
- `Floating`
  - rounded corners/fillets restored
  - floating-window shadow/chrome treatment restored
- `Pop-Out`
  - full-window docked shell
  - no fillets

Important rule:
- `Floating` should look intentionally like a movable window
- `Docked` and `Pop-Out` should look intentionally like shell-owned docked surfaces

### Important Interfaces And Types

- `ConsoleWindowMode = 'docked' | 'floating' | 'popout'`
- app-level console window state for:
  - current mode
  - floating rect:
    - `x`
    - `y`
    - `width`
    - `height`
  - last floating rect
  - pop-out open/closed ownership truth
- narrow console window actions for:
  - switch to docked
  - switch to floating
  - switch to pop-out
  - set floating rect
  - handle child-window close/fallback

### First-Pass Integration Shape

`4.1B` should extend the shipped `4.1A` console shell, not re-architect the whole console.

The implementation should stay centered around:
- `AppShell` placement/ownership in the main app shell
- the current console state/store area
- the current console shell components
- the shared console styling surface

Likely implementation seams:
- `src/app/AppShell.tsx`
- `src/app/console/`
- `src/app/theme/v15Theme.css`

### Locked Deferrals

Keep these out of `4.1B`:

- new command-language work
- transcript persistence or export
- hotkey rebinding
- multiple pop-out windows
- simultaneous expanded-console ownership in both main app and pop-out window
- replacing the debug inspector

Those belong in later `4.1C+` follow-ups.

### Test Plan

- switching from `Docked` to `Floating` enters floating mode correctly
- switching from `Floating` back to `Docked` returns to the docked shell correctly
- switching from `Docked` or `Floating` to `Pop-Out` opens the child browser window correctly
- the floating console can be dragged by its header
- the floating console can be resized from any edge and corner
- floating move/resize behavior is clamped to the visible viewport
- the floating rect is restored within the current session when re-entering floating mode
- opening `Pop-Out` makes the child window the only expanded-console owner
- while popped out, the main app still shows the collapsed bottom row
- while popped out, the main app does not show a second expanded console
- closing the pop-out child window returns the main shell to collapsed-only mode
- transcript continuity is preserved across `Docked`, `Floating`, and `Pop-Out`
- tool state and layer visibility remain intact across mode changes
- styling differs correctly:
  - docked = no fillets
  - floating = fillets restored
  - pop-out = no fillets

### Assumptions And Defaults

- this task is docs-only: prepare the `04.1B` phase doc, not app code
- `04.1A` remains the shipped baseline and `04.1B` is a direct extension of that delivered shell
- separate header controls are the locked mode-switch approach for `4.1B`
- `Single owner` is the locked pop-out model for the expanded console
- closing the pop-out restores only the collapsed row in the main shell
