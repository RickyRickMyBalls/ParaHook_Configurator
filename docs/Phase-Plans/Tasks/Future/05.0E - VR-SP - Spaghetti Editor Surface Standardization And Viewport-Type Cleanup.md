### Still Needed Decisions

#### `5.0E.Q1` - What is the canonical graph-editor viewport type?

Suggested answer:
- `Spaghetti Editor`

Why:
- it already behaves like the strongest real editor surface
- it already participates in split behavior more honestly than the compact docked editor variant
- it is the safest viewport-type name to standardize before `[5.1]`

#### `5.0E.Q2` - What is the `meatball editor`?

Suggested answer:
- treat it as a compact editor presentation of the editor family, not the first canonical viewport type

Why:
- it currently reads like a docked compact shell host
- it is useful in the left-dock workflow
- but it should not necessarily define the first standardized viewport-type vocabulary for the workspace system

#### `5.0E.Q3` - Should `meatball editor` still be allowed as a viewport later?

Suggested answer:
- maybe later, but do not require that decision before `[5.1A]`
- first standardize the full `Spaghetti Editor`
- then decide whether `meatball editor` becomes:
  - a compact mode
  - a sub-type
  - or a true later viewport type

Why:
- this keeps the first viewport-type list clean
- it avoids forcing the workspace lane to harden around a compact editor variant too early

#### `5.0E.Q4` - What names should become standard before `[5.1]`?

Suggested answer:
- user-facing canonical graph-editor viewport type:
  - `Spaghetti Editor`
- compact docked variant:
  - `Meatball Editor`
- architecture term:
  - `editor surface family`

Why:
- this lets the docs distinguish:
  - the main viewport type
  - the compact presentation
  - the broader editor family

#### `5.0E.Q5` - What should the first standardized viewport-type list assume?

Suggested answer:
- first-pass viewport-type list should assume:
  - `Model Viewer`
  - `Browser`
  - `Spaghetti Editor`
  - `Console`
  - `Gizmo / View`
- keep `Meatball Editor` out of the first canonical list unless it is later promoted intentionally

Why:
- this makes the first Blender-style `switch viewport type` menu easier to explain
- it gives the workspace lane one honest first list instead of mixing main surfaces with compact variants
