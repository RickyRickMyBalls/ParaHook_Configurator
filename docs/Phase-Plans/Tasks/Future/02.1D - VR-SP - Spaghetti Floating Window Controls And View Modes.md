### Locked Window Mode Contract

`EditorViewportWindowMode` should become:
- `'collapsed'`
- `'meatball editor view'`
- `'expanded'`
- `'maximized'`
- `'split view'`
- `'separateWindow'`

Working read:
- `collapsed`
  - header-only strip
  - editor body hidden
  - top editor bar/icons remain visible over the model viewport
- `expanded`
  - normal floating overlay editor
  - draggable
  - resizable
- `maximized`
  - full in-app overlay over the model viewport
  - not detached
- `split view`
  - docked non-overlay layout
  - model viewport on top
  - `Spaghetti Editor` on bottom
  - divider between them
- `meatball editor view`
  - minimized editor surface hosted in the left dock below `Parts List`
- `separateWindow`
  - remains defined but deferred

### Locked Viewport-Owned State Additions

Each editor viewport should gain:
- `splitRatio: number`
- `restoreFromCollapsed: { windowMode: 'expanded' | 'maximized' | 'split view'; position?: { x: number; y: number }; size?: { width: number; height: number }; splitRatio?: number } | null`
- `restoreFromSplit: { windowMode: 'expanded' | 'maximized'; position?: { x: number; y: number }; size?: { width: number; height: number } } | null`

Rules:
- `restoreFromCollapsed` stores the previous non-collapsed state captured when entering `collapsed`
- `restoreFromCollapsed` is cleared once collapsed mode is exited through collapse-toggle restore
- `splitRatio` is only used by `split view`
- `splitRatio` defaults to `0.5`
- `splitRatio` clamps to `0.25..0.75`
- `restoreFromSplit` stores the previous non-split state captured when entering split mode
- `restoreFromSplit` is cleared once split mode is exited through split-toggle restore

### Locked Titlebar Button Behavior

From non-collapsed states:

`collapse`
- `expanded|maximized|split view -> collapsed`
- capture previous non-collapsed state into `restoreFromCollapsed`
- hide the editor body
- leave only the top editor bar/icons visible so the user can quickly see the model

`meatball editor view`
- move the active editor into the dedicated left-dock meatball panel
- restore the model viewport to full size

`maximize`
- `expanded -> maximized`
- `maximized -> expanded`
- restore target for `maximized -> expanded` is the standard default floating-editor size/position
- do not restore an arbitrary previously stretched floating geometry

`split view`
- `expanded|maximized -> split view`
- capture previous non-split state into `restoreFromSplit`
- enter split at `splitRatio = 0.5`

`X`
- close the active editor surface using the existing viewport close path

### Locked Collapsed-Mode Button Behavior

While already in `collapsed`:

`collapse`
- acts as a toggle
- clicking it again exits collapsed mode
- restore the captured previous non-collapsed state from `restoreFromCollapsed`

`meatball editor view`
- exit collapsed
- restore full model viewport
- move the editor into the dedicated left-dock meatball panel

`maximize`
- exit collapsed
- switch to `maximized` overlay mode over the model viewport

`split view`
- exit collapsed
- switch to `split view` at `splitRatio = 0.5`

`X`
- close the editor surface

### Locked Split-Mode Button Behavior

While already in `split view`:

`collapse`
- exit split
- enter `collapsed`
- keep only the top editor bar/icons visible over the model viewport

`meatball editor view`
- exit split
- restore full model viewport
- move the editor into the dedicated left-dock meatball panel

`X`
- exit split
- close the editor surface

`split view`
- acts as a toggle
- clicking it again exits split mode
- restore the captured previous non-split state from `restoreFromSplit`

`maximize`
- exit split
- switch to `maximized` overlay mode over the model viewport

Separate-browser arrow
- out of scope because the button is deferred entirely in this phase

### Locked Split-Mode Behavior

Split mode must be:
- non-overlay
- vertically stacked
- top = model viewport
- bottom = `Spaghetti Editor`

Divider rules:
- start at a sensible default half-height ratio
- expose a user-draggable divider
- allow the user to rebalance the top viewport area and bottom editor area
- persist the current `splitRatio` on the viewport while that viewport remains alive

Plain-English rule:
- split mode starts around `50/50`
- then the user can drag the divider to give more room to the viewport or the editor

### Locked Collapsed Behavior

`collapsed` is:
- a true quick-hide editor state
- header-only
- still visible in the viewport area

It is not:
- a docked panel
- the same thing as `meatball editor view`

Working distinction:
- `collapsed`
  - quick model-view mode with only the editor bar/icons shown
- `meatball editor view`
  - docked minimized editor host below `Parts List`

### Locked Meatball Behavior

`meatball editor view` is:
- the minimized state of the same editor surface
- not a separate tool

Render target:
- a new dedicated left-dock panel below `Parts List`

It is not:
- embedded inside `Toolbar`
- embedded inside `PartsListPanel`

### Current Seam Findings

`AppShell.tsx`
- currently owns the visible floating-editor shell
- currently renders only one active overlay presentation
- is the correct owner for:
  - expanded floating overlay
  - maximized overlay
  - split layout
  - meatball dock-panel host

`useSpaghettiStore.ts`
- already owns viewport-local `windowMode`
- already has `setEditorViewportWindowMode(...)`
- already enforces the single `meatball editor view` rule
- is the correct owner for:
  - new `windowMode` values
  - `splitRatio`
  - `restoreFromCollapsed`
  - `restoreFromSplit`

`spaghettiTypes.ts`
- already defines `EditorViewportWindowMode`
- is the correct place to extend the viewport shell contract

`SpaghettiPanel.tsx`
- should remain the reusable editor body across:
  - expanded
  - maximized
  - split
  - meatball host surfaces

### Recommended Implementation Order

1. Extend `EditorViewportWindowMode` and viewport state with `maximized`, `split view`, `splitRatio`, `restoreFromCollapsed`, and `restoreFromSplit`.
2. Add or update store actions so collapse entry/exit, split entry/exit, maximize toggle, and meatball transitions are viewport-owned and deterministic.
3. Replace the top-right `Drag` label in the rendered shell with explicit titlebar buttons, including `__` for collapse.
4. Implement true `collapsed` header-only mode.
5. Implement `maximized` overlay mode and its toggle-back-to-default behavior.
6. Implement `split view` rendering and divider resizing.
7. Implement collapsed-mode and split-mode button transitions.
8. Add the dedicated left-dock `meatball editor view` host below `Parts List`.
9. Leave detached/new-browser behavior untouched and visibly absent from this phase.

### Deferred / Out Of Scope

Defer to `SP - Phase 13`:
- visible separate-browser titlebar control
- real detached/new-browser editor windows
- multi-window shell rendering across more than one visible spaghetti-editor window
