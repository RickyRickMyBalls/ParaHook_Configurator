### Problem Statement

`2.1A` made the Browser rows intentional and Browser-local:
- graph rows, published output rows, and viewport rows share one row anatomy
- row-body click creates local Browser selection
- explicit `Open` and `Focus` actions already exist

But the app still does not clearly define:
- how Browser rows should point at editor focus without silently moving it
- how Browser rows should point at the shared viewer without inventing a new emphasis system
- how shared composition should appear in the Browser without making the Browser a composition-authoring surface

`2.1B` needs to add that coordination layer while preserving the clear separation already created in `2.1A`.

### Locked Browser / Editor Coordination Rule

`2.1B` keeps one clear rule:
- row-body click remains Browser-local selection only
- Browser selection does not automatically equal editor focus
- explicit actions remain the only path that moves editor state

First-pass explicit editor actions remain:
- graph row:
  - `Open`
  - `New Editor`
  - `Swap Editor`
- viewport row:
  - `Focus`

Plain-English rule:
- Browser rows may point at editor context, but only explicit actions move editor focus

### Locked Browser / Shared Viewer Coordination Rule

`2.1B` should let Browser rows point at the shared viewer through one explicit coordination path:
- `Reveal`

`Reveal` is:
- explicit
- presentation-oriented
- read-only with respect to ownership

`Reveal` must not:
- change graph/project ownership truth
- silently change shared composition membership
- invent a new generic viewer-emphasis state

### Locked Reveal Entry Path

The first shared-viewer entry path is:
- an explicit `Reveal` row action

Apply `Reveal` to:
- graph rows
- published-output rows

Do not use for the first pass:
- row-body click
- implicit reveal on hover
- automatic reveal on selection change

Why this cut is correct:
- it preserves the `2.1A` separation between selection and coordination
- it keeps the user-facing meaning of reveal explicit
- it avoids muddying the Browser row-body click semantics immediately after `2.1A`

### Locked Shared Composition Status Rule

When shared composition is active:
- Browser rows may show read-only participation status for graphs already in shared composition
- Browser rows must not add or remove composition membership in this phase

That means:
- no Browser-authored composition membership actions
- no composition ordering actions
- no multi-graph shared-viewer workflow authoring from the Browser

Plain-English rule:
- the Browser may show composition status, but not control composition membership

### Locked First-Pass Reveal Unit

The first reveal unit is:
- graph-scoped

That means:
- clicking `Reveal` on a graph row targets that graph document
- clicking `Reveal` on a published-output row still targets its source `graphDocumentId`

This phase does not introduce:
- output-scoped viewer targeting
- per-output emphasis state
- cross-graph emphasis targets

Why this cut is correct:
- the current viewer/store seam already supports graph-targeting through `viewerTargetGraphDocumentId`
- the current app does not yet have a separate cross-graph emphasis target model

### Current Seam Findings

- already has Browser-local selection from `2.1A`
- already has explicit graph `Open` and viewport `Focus` actions
- is the correct UI surface for adding explicit `Reveal` actions and read-only composition-status display

- already owns the shared Browser row-shell contract
- is the correct place to add:
  - `Reveal` action metadata

- should remain a read model, not a new ownership source

- already owns:
  - `setActiveEditorViewportId`
  - `setViewerTargetGraphDocumentId`
  - shared composition state and selectors
  - composition membership authoring APIs that must stay out of Browser rows here
- does not need a new generic emphasis state for this first pass

`ViewerHost.tsx`
- already switches between:
  - single-target viewer mode
  - shared composition mode
- the existing seam supports graph-target reveal through `viewerTargetGraphDocumentId`
- it does not currently imply a separate output-level or cross-graph emphasis target

### Implementation Order

1. Extend the Browser row selector contract with coordination-facing action/status metadata for `2.1B`.
2. Add explicit `Reveal` actions to graph and published-output rows.
3. Wire `Reveal` to `setViewerTargetGraphDocumentId` only when shared composition is not active.
4. Add read-only shared-composition participation status to graph rows.
5. Keep row-body click, editor actions, and shared composition membership behavior unchanged.
6. Stop before any new emphasis-state model or Browser-authored composition workflows.

### Acceptance / Proof Bar

`2.1B` is complete when:
- selecting a Browser row still does not move editor focus
- clicking `Open` on a graph row still opens/focuses that graph in the editor
- clicking `Focus` on a viewport row still focuses that viewport
- clicking `Reveal` on a graph row sets `viewerTargetGraphDocumentId` when shared composition is not active
- clicking `Reveal` on a published-output row targets its source graph, not a new output-level viewer state
- when shared composition is active, Browser rows show participation status but do not add/remove composition membership
- Browser actions do not silently retarget shared composition or mutate composition membership
- no new store-owned emphasis state or ownership truth is created
