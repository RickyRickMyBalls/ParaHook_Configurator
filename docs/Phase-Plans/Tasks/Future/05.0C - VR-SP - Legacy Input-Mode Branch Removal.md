## Doc Body

### Summary

`5.0C` is the cleanup cut that actually removes the legacy input branch from code.

This phase should:
- stop treating `legacy` as a real input mode
- remove the remaining branch conditionals that still exist only to preserve that old mode
- leave the app as spaghetti-first without hidden legacy-input fallback logic

### Locked Outcome

At the end of `5.0C`:
- `inputMode` no longer models `legacy` versus `spaghetti`
- `viewMode` no longer models `parts` versus `assembled`
- the app no longer depends on hidden `legacy` routing to remain usable
- viewer/build/panel logic no longer branches on that old mode split

### Locked Removal Order

Do not remove the branch in one blind pass.

Recommended order:
1. collapse `useAppStore` onto one spaghetti-era path
2. remove `InputMode = 'legacy' | 'spaghetti'`
3. remove `ViewMode = 'parts' | 'assembled'`
4. simplify `ViewerHost` to one viewer path
5. remove legacy-only runtime branches from `Toolbar.tsx` and `PartsListPanel.tsx`
6. leave dead files for `5.0D`

Important rule:
- `5.0C` should finish the runtime branch removal
- `5.0D` should clean up the dead residue after that branch is gone

### Locked Removal Rules

#### `InputMode`

`inputMode` should no longer model `legacy` versus `spaghetti`.

Locked direction:
- remove `InputMode = 'legacy' | 'spaghetti'`
- remove `setInputMode`
- stop storing branch identity that no longer represents a real user choice

#### `ViewMode`

`viewMode` should no longer model `parts` versus `assembled`.

Locked direction:
- remove `ViewMode = 'parts' | 'assembled'`
- remove `setViewMode`
- remove the old assembled-cache toggle behavior with the rest of the legacy viewer split

#### Store Branches

Legacy-only behavior should be collapsed onto one spaghetti-era path.

Locked direction:
- remove legacy-only conditionals in `useAppStore`
- do not preserve `legacy` request/build routing "just in case"
- if a capability is still needed, re-express it as a real spaghetti-era behavior instead of preserving the old branch name

#### Viewer Routing

`ViewerHost` should no longer branch on `legacy` versus `spaghetti`.

Locked direction:
- remove `inputMode` checks that only decide between old legacy preview and spaghetti preview paths
- keep only the viewer behavior that still makes sense after spaghetti becomes the only real authoring/input system

### Locked Viewer Rule

`parts / assembled` does not survive `5.0C`.

Locked direction:
- `ViewerHost` should render one spaghetti-era preview path
- remove assembled-cache toggles and old viewer branching with the legacy branch
- do not preserve `parts / assembled` as a separate concept after the runtime collapse

### Locked Cleanup Boundary

`5.0C` removes runtime dependence and unreachable branch logic.

`5.0D` removes:
- dead files
- stale CSS
- stale imports
- ambiguous post-branch residue

#### Panel And Surface Cleanup

`5.0C` should remove branch logic from runtime surfaces even if the surfaces themselves are already out of the shell.

Locked direction:
- remove the old `Toolbar.tsx` input-mode branch UI and related dead code
- remove `PartsListPanel.tsx` legacy-only control branches if the file still survives temporarily
- do not treat hidden/unmounted files as a reason to keep the branch alive

### Locked Preservation Rule

The goal is not to preserve the `legacy` path under a new name.

Preserve only:
- real spaghetti-era build behavior
- real viewer behavior that still makes sense without the branch
- real error/reporting behavior through the `Console`

Do not preserve:
- dead `legacy` compatibility toggles
- hidden `setInputMode('legacy')` escape hatches
- legacy-only build triggers that no longer represent a real user workflow

### Non-Goals

`5.0C` does not:
- complete the broad final legacy purge from `[5.6]`
- decide the permanent long-range home of every dead file
- guarantee that `PartsListPanel.tsx` or `BoxPanel.tsx` are deleted in this same cut
- absorb workspace-mode work from `[5.1]`

### Locked Removal Rule

Do not treat `5.0C` as only UI cleanup.

It must:
- remove the legacy input-mode branch from state and behavior
- remove the remaining conditional seams that only exist because of that branch

Important rule:
- only start `5.0C` after `5.0A` and the main shell cleanup are already in place

### Verification / Proof Bar

`5.0C` should prove all of these:
- `useAppStore` no longer exposes or depends on `InputMode = 'legacy' | 'spaghetti'`
- `useAppStore` no longer exposes or stores `viewMode = 'parts' | 'assembled'`
- `setInputMode` is removed or reduced away from the old branch meaning
- `setViewMode` is removed
- `requestManualBuild` still works on the spaghetti-era path
- no ordinary runtime flow can request the old legacy-only build path
- `ViewerHost` no longer reads `inputMode` or `viewMode`
- changing legacy box params or legacy instance lists no longer triggers preserved `legacy` build routing
- the old `Toolbar.tsx` branch UI is gone or unreachable because the file no longer carries real branch logic
- spaghetti-first startup from `5.0A` still works
- left-dock cleanup from `5.0B` still holds
- worker/build issues still surface through the `Console`
