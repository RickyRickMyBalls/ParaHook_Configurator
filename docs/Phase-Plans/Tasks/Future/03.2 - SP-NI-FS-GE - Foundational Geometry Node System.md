## Arch Spec

### Spec Target

This implementation target is only:
- `[3.2] SP / NI / FS / GE - Foundational Geometry Node System`

This cut intentionally sits:
- after enough generic node cleanup in `[3.1]` that the node system can host the first geometry nodes honestly

### Problem Statement

ParaHook now has a clearer architecture direction for foundational geometry authoring, but that direction still lives mostly in planning language.

The missing step is to turn that into an executable first geometry-node system that proves:
- the graph can carry the right data types
- `Sketch` can act as a real geometry-authoring node
- `Extrude` can produce the first body result
- `Loft` can follow as the next real profile-based solid feature

Without this phase:
- the node system stays too shell-like
- feature-stack direction stays abstract
- the graph-native CAD promise remains under-specified in code

### Locked First-Pass Win

`[3.2]` counts as real when:
- the first required geometry data types are explicit
- `Sketch` exists as a real node and not only a planning idea
- the first sketch-operation flow produces a usable profile result
- `Extrude` produces a body from that profile
- `Loft` is defined as the next real body feature after `Extrude`

Plain-English rule:
- make the graph capable of one honest end-to-end geometry authoring slice

### Locked `Sketch` Product Hierarchy

By the end of `[3.2]`, the `Sketch` node should read like one main user-facing node, not a pile of separate top-level graph nodes:

```text
Sketch
├─ Inputs
├─ Draw/Edit Curves Inside
├─ Close/Select Profile
└─ Outputs
```

Expanded first-pass product shape:

```text
Sketch
├─ Inputs
│  └─ SketchPlane : [Plane]
├─ Draw/Edit Curves Inside
│  ├─ Line
│  ├─ Arc3Point
│  └─ BezierSpline
├─ Close/Select Profile
│  ├─ CloseProfile
│  └─ ProfileSelect
└─ Outputs
   ├─ SketchProfiles : [SketchProfiles]
   └─ SketchProfile : [SketchProfile]
```

Hierarchy rule:
- `Inputs` and `Outputs` are top-level shell structure
- curve authoring and profile-closure/selection live inside the `Sketch` node body
- `Sketch` should feel like one authored tool surface that later feeds `Extrude` and `Loft`

Viewer-integration rule:
- `Draw/Edit Curves Inside` should eventually include a dedicated sketch-only viewer toolbar and viewport-edit mode
- that viewer mode belongs to the active `Sketch` node and edits the same underlying sketch state as the node body
- `Sketch in Viewer` should be treated as internal `Sketch` authoring depth, not as a separate feature family outside the node

Draw-row rule:
- the next neat row after plane setup is the `Draw` row inside `Draw/Edit Curves Inside`
- activating `Draw` should collapse/minimize the spaghetti editor and open the sketch toolbar as a floating window over the model viewport
- the first draw-tool set should include:
  - `Line`
  - `Arc`
  - `Spline`
  - `Rectangle`
  - `Circle`
- first-pass sketch lines, points, handles, and preview geometry should be rendered by ParaHook's own viewer-side overlay/runtime rather than assuming Replicad will display editable sketch entities
- confirming draw mode should reopen the spaghetti editor and populate the `Draw` area with the authored entities

Close/select rule:
- the next row after `Draw` should be `Close / Select Profile`
- its action should be `Review`, not `+`
- `Review` should re-enter the viewer in profile-review mode so the user can inspect and choose a closed loop
- confirming that choice should reopen the spaghetti editor and summarize the selected profile in the row

Input-row rule:
- the `Inputs` section should be organized into explicit rows rather than loose controls
- the first required input row is `SketchPlane`
- the `SketchPlane` row should remain a real graph input row with its own input pin
- the `SketchPlane` row should expose a right-side `+` action to start plane picking
- wiring a plane into that pin should be a first-class assignment path
- activating that action should collapse/minimize the spaghetti editor into plane-pick mode
- the first plane-pick surface should show ghost preview planes/grids around the origin for:
  - `XY`
  - `XZ`
  - `YZ`
- later, the same flow can expand to allow clicking any planar face to create the sketch plane

### [3.2A] Data Types And Sketch Foundation

Primary targets:
- `[Float]`
- `[Boolean]`

- `[Vec2]`
- `[Plane]`

Deferred or optional in `[3.2A]`:

- `[Transform2D]`
- `[SketchCurve]`
- `[SketchCurveRef]`
- `[SketchCurves]` only if it can be exposed honestly without inventing fake early curve-ref contracts

### [3.2B] Sketch Operation Authoring

Primary targets:
- fill the `Draw/Edit Curves Inside` section with:
  - `SketchLine`
  - `SketchArc3Point`
  - `SketchBezierSpline`
  - `SketchRectangle`
  - `SketchCircle`
- fill the `Close/Select Profile` section with:
  - `SketchCloseProfile`
  - `SketchProfileSelect`
- preserve the existing `closeProfile -> profileRef -> extrude` compatibility seam under the hood while presenting review/selection as part of the integrated `Sketch` workflow

Deferred unless necessary:
- `SketchMirror`
- `SketchProject`
- `SketchTrim`
- `SketchOffset`

### [3.2C] Extrude Foundation

Primary targets:
- `ExtrudeType`
- `Basic` mode required inputs
- first body-producing output
- one selected-profile plus positive-depth proof path

Deferred unless necessary:
- `Twist` execution completion beyond what is needed to lock the first contract
- direction/origin/start controls beyond the first honest profile-plus-depth surface
- taper/offset as active first-pass public behavior

### [3.2D] Loft Foundation

Primary targets:
- `LoftType`
- `Basic` mode required inputs
- first loft body output

Deferred unless necessary:
- `RailGuided` mode completion beyond what is needed to lock the first contract
