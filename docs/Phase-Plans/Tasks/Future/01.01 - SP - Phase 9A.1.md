## Arch Spec

### Spec Target

This implementation target is only:
- `[1.1A.1] SP - Phase 9A.1 - Graph Document Shape And Identity`

If this cut is wrong, later work has no stable base for:
- `9A.2` graph-owned authored canvas state
- `9A.3` viewport binding
- `9B` multi-editor Browser behavior
- `GE 11` save/load
- `SP 10` graph-aware routing
- `GE 12` project ownership

So this cut should stay small, explicit, and durable.

### Problem Statement

The current runtime still behaves like:
- one implicit active graph
- one spaghetti store acting like the only real document
- one editor surface acting too much like the graph owner

That is incompatible with the roadmap direction:
- graphs are first-class document-like objects
- editors are viewports into graphs
- Browser/project layers sit above graph documents later

### Current Execution Rules

Code-grounded rules for this cut:

- `useSpaghettiStore.graph` is the current real graph owner and must stop being the canonical document shape.
- `useAppStore` currently acts as a spaghetti bridge and must stop reading raw singleton graph state directly for canonical graph identity.
- `inputMode` stays temporarily, but only as UI mode state.
- `SpaghettiEditor` and `SpaghettiCanvas` are consumers and mutators of graph data, not document owners.

### Seams To Break In 9A.1

This cut only needs to break the seams required for the first document layer:

1. singleton graph ownership in `useSpaghettiStore`
2. imperative app-store access to raw singleton graph state
3. direct panel/editor/canvas singleton graph reads
4. missing explicit document identity in runtime graph access

Follow-on note:
- viewport-manager work belongs to `9A.3` and `9B`, not this cut

### Canonical First-Pass Contract

`9A.1` should lock this contract:

```ts
type GraphDocument = {
  graphDocumentId: string
  name: string
  version: number
  graph: SpaghettiGraph
}
```

### Contract Rules

#### Required

- `graphDocumentId` is required and stable
- `name` is required but is not the identity key
- `version` is required and starts at `1`
- `graph` is the canonical authored payload

#### Deferred Out Of `9A.1`

- `origin`
- `authoredCanvasState`
- viewport state
- selection/hover/drag state
- build/preview/output handoff state
- project/file ownership state

If the code already has unavoidable runtime data around these areas, do not treat that as permission to move them into the first canonical contract.

### Ownership Rules

#### Canonical `GraphDocument` truth

`GraphDocument` owns:
- document identity
- document name
- document version
- raw `SpaghettiGraph` payload

#### Not part of `9A.1` canonical truth

Do not place these on the first `GraphDocument` contract:
- editor window state
- focus/selection/hover state
- canvas pan/zoom state
- `connectionDrag`
- `uiMessage`
- `edgeWaypoints`
- compile/build caches
- project-local Browser ownership

### `9A.1` Decision Defaults

#### `edgeWaypoints`

Decision:
- real runtime editing data, but not canonical graph-document state in `9A.1`

Why:
- they are editable wire-shape controls in the canvas runtime
- they are not part of the canonical `SpaghettiGraph` schema today
- `OutputPreview` and cube-related connections run through normal `SpaghettiEdge` topology, not waypoint-owned graph structure

#### node row mode

Decision:
- defer implementation to `9A.2`, but treat it as future graph-authored canvas state

#### composite expansion

Decision:
- viewport/editor-local

#### selection / hover / `connectionDrag` / `uiMessage`

Decision:
- viewport/editor-local

#### `useSpaghettiStore`

Decision:
- keep temporarily, but narrow it away from singleton graph ownership over time

#### `inputMode`

Decision:
- keep temporarily as UI mode state only

# Close Out notes

## What This Phase Actually Proved

- `GraphDocument` is a workable first cut for graph identity without needing Browser or project ownership yet.
- the app could absorb a document layer without needing a full rewrite of the editor runtime first.
- keeping the old `graph` field as a temporary bridge made the `9A.1` cut faster and safer while still moving canonical identity to the document layer.
- the real hard part was not the schema shape; it was reconnecting all the graph consumers cleanly.

## What We Learned During Implementation

- `useSpaghettiStore` was doing two jobs at once:
  - canonical graph ownership
  - editor/runtime interaction ownership
- splitting those concerns starts paying off immediately once graph identity becomes explicit.
- `useAppStore` was not the true graph owner, but it was tightly coupled to the old singleton seam through compile/build access.
- a lot of the runtime did not need large logic changes; many consumers only needed to stop reading `state.graph` directly and instead read the active graph through the document layer.
- `inputMode` can stay for now as a UI mode toggle without blocking the architecture shift, as long as it is not treated as graph identity.

## Good Decisions In `9A.1`

- keeping the canonical `GraphDocument` contract small was the right move:
  - `graphDocumentId`
  - `name`
  - `version`
  - `graph`
- deferring `authoredCanvasState` was correct; it would have mixed the `9A.1` identity cut with `9A.2` ownership work.
- deferring `edgeWaypoints` from canonical document state was also correct.
- adding selectors like `selectActiveGraphDocument` and `selectActiveGraph` was the right seam because it gives later phases a stable reconnect point.

## Things Still Intentionally Transitional

- `useSpaghettiStore.graph` still exists as a synced bridge field.
- active document support is still effectively one-document runtime behavior even though the shape now allows more.
- editor-local state is still mixed into the same store in several places.
- the app still does not have real viewport binding by `graphDocumentId`.
- Browser/project ownership is still out of scope and not started by this cut.

## Main Risks For Future Phases

- do not let the temporary `graph` bridge become permanent again.
- do not let `9A.2` silently pull in `9A.3` or `9B` work.
- do not move viewport-local state into graph documents just because it is convenient during refactor.
- do not let compile/build routing decisions leak into document-shape decisions; that belongs later.
- be careful with `SpaghettiCanvas.tsx`; it remains one of the heaviest seam files in the runtime.

## What To Watch In `9A.2`

- decide the exact authored-canvas state that truly belongs to the graph document.
- separate graph-authored canvas truth from view-only/editor-local state cleanly.
- be especially explicit about:
  - node row mode
  - any future durable wire-shape data
  - any node expansion/collapse state that might be authored versus local
- avoid broad UI cleanup work that is not required for graph-owned canvas state.

## What To Watch In `9A.3`

- make `graphDocumentId` the real editor/viewport binding key.
- stop assuming “the spaghetti editor” is the owner of the graph.
- treat the editor as a viewport into a graph document, not the graph container itself.
- keep focus/z-order/window behavior separate from graph-authored state.

## What To Watch In `9B` And `9C`

- `9B` should build honest viewport coordination on top of the new document identity, not reinvent document ownership.
- `9C` should move compile/build/preview-prep memory toward graph-local ownership using the new identity seam instead of reaching back into singleton assumptions.
- both phases should reuse the selectors/document layer from `9A.1` rather than creating new parallel access paths.

## Recommended Rule Going Forward

- when a seam is intentionally disconnected, write down:
  - what was disconnected
  - what temporary bridge remains
  - what phase is responsible for the reconnect
- keep future cuts small and phase-pure the same way `9A.1` was kept small.
- prefer stable reconnect seams over broad “big bang” rewrites.
