### Problem Statement

The current planning language already describes a useful `Sketch` shell, but the graph still lacks the first honest sketch-operation flow that would make that shell productive.

Without this cut:
- `Sketch` stays too empty to matter
- `Extrude` has no reliable selected-profile source
- the foundational geometry lane stalls at shell language instead of usable authoring

### Locked First-Pass Win

`[3.2B]` counts as real when:
- the first sketch-operation set is explicit and shipped inside the `Sketch` workflow
- the user can author geometry in the viewer and get back to a populated `Draw` list in the editor
- the user can review detected loops and select one downstream-ready profile
- the existing `closeProfile -> profileRef -> extrude` compatibility path still works
- deferred sketch depth stays clearly out of the first ship cut

Plain-English rule:
- make `Sketch` capable of one honest downstream-ready profile, not every possible sketch behavior

### Locked Sketch Authoring Model

`Sketch` remains one integrated user-facing node.

The first-pass user flow is:
1. Assign `SketchPlane`.
2. Enter `Draw`.
3. Draw/edit entities in the viewer with a floating sketch toolbar.
4. Confirm draw mode.
5. Reopen the spaghetti editor with the `Draw` list populated.
6. Enter `Close / Select Profile` via `Review`.
7. Review detected loops in the viewer.
8. Confirm one selected profile.
9. Reopen the spaghetti editor with the selected profile summarized in the row.

Implementation rule:
- `Draw` is the active authoring row inside `Draw/Edit Curves Inside`
- `Close / Select Profile` is the next row and uses `Review`, not `+`
- the node body and the viewer edit the same underlying sketch state

### Locked Draw Row Shape

The `Draw` section should behave like this:

```text
Sketch
└─ Draw/Edit Curves Inside
   └─ Draw row
      ├─ label: Draw
      ├─ state: idle or active tool
      └─ action: enter draw mode
```

First `Draw` row behavior:
- activating `Draw` collapses/minimizes the spaghetti editor
- the viewer opens the sketch toolbar as a floating window on top of the model viewport
- the toolbar becomes the active command surface while the viewport becomes the live drawing surface
- confirming draw mode closes the floating toolbar, reopens the spaghetti editor, and restores the normal editor state
- once draw mode is confirmed, the `Draw` section populates with the authored entities in row-list form

### Locked Viewer Toolbar

The first toolbar is a dedicated sketch-only toolbar that appears only while a `Sketch` node is actively being edited in the viewer.

First-pass toolbar sections:
- plane/edit mode context:
  - active sketch name
  - active sketch plane
  - exit sketch mode
- draw tools:
  - `Line`
  - `Arc`
  - `Spline`
  - `Rectangle`
  - `Circle`
- edit actions:
  - `Delete Selected`
  - `Cancel Current Draw`
- review actions:
  - `Confirm Draw`
  - `Back To Draw`
  - `Done`

Viewer-mode rule:
- the floating draw toolbar owns only active command state
- it does not own persistent sketch data

### Locked Shape Storage And Lowering

`Rectangle` and `Circle` are first-class authored sketch component types in stored sketch state.

Storage rule:
- `SketchFeature.components` stays the single source of truth for authored geometry
- authored shape identity is preserved in stored sketch state
- shapes are not immediately flattened when the user confirms the draw

Lowering rule:
- `rectangle` lowers to 4 `line2` segments for derivation/runtime
- `circle` lowers to 2 `arc3pt2` half-circle segments for derivation/runtime
- `line`, `arc3pt`, and `spline` continue to lower directly from their stored authored form

Compatibility rule:
- lowering happens inside derivation/runtime seams, not at the viewer-authoring seam

### Locked Viewer Rendering Rule

The first pass must not assume Replicad will show editable sketch entities.

Render in ParaHook viewer code:
- sketch lines
- sketch points
- handles
- hover highlights
- temporary preview geometry
- detected-loop highlights during profile review

Runtime rule:
- if the user is drawing or editing a sketch entity in the viewport, ParaHook renders that entity itself
- Replicad remains downstream for solid/body work only

### Locked Snapping Rule

First-pass snapping includes:
- grid snapping
- endpoint snapping

First-pass snapping excludes:
- midpoint snapping
- trim/extend smart behavior
- constraint-driven inference
- advanced snap taxonomies beyond what is needed for one honest closed-profile path

### Locked Close / Select Profile Row

After the `Draw` section is populated, the next row is:

```text
Sketch
└─ Close / Select Profile
   └─ Profile row
      ├─ label: Close / Select Profile
      ├─ summary: detected profile count / selected profile
      └─ action: Review
```

Row behavior:
- do not use a `+` action here
- the row action is `Review`
- `Review` collapses/minimizes the spaghetti editor again and re-enters the viewer in profile-review mode
- the viewer highlights detected closed loops for the current sketch
- hovering a loop previews it
- clicking a loop selects it as the downstream-ready profile
- confirming the selection reopens the spaghetti editor and populates the row with the chosen profile summary

Selection rule:
- if exactly one valid closed profile exists, preselect it automatically
- if multiple valid profiles exist, require explicit user selection

### Locked Managed Compatibility Seam

`[3.2B]` keeps the current internal `closeProfile` seam under the hood.

Implementation rule:
- new sketch workflow uses a sketch-managed internal `closeProfile` companion
- the user interacts with `Close / Select Profile` as a row inside `Sketch`, not as a separate top-level workflow for new sketches
- legacy standalone `closeProfile` data remains readable
- downstream `Extrude` compatibility continues through the existing `closeProfile -> profileRef -> extrude` path

### Ownership And Sync Rules

Lock these ownership rules for the first pass:
- the `Sketch` node owns the source of truth for sketch components and outputs
- the viewer owns only transient interaction state:
  - active tool
  - hover
  - temporary preview geometry
  - selected point/handle
- node-side numeric editors and viewer-side direct manipulation both write back into the same sketch component list
- profile derivation stays downstream of that one shared component list

## Implementation Order

1. Extend sketch authored component types and schema support for `rectangle` and `circle`.
2. Extend derivation/runtime lowering so those shapes resolve to supported segments.
3. Add viewer sketch session state for draw mode and profile-review mode.
4. Add ParaHook viewer overlay rendering for lines, points, handles, hover, and preview geometry.
5. Rework `SketchFeatureView` so `Draw` enters viewer mode and repopulates the entity list on confirm.
6. Implement sketch-managed `Close / Select Profile` review flow while preserving the internal `closeProfile` seam.
7. Wire selected-profile review results back into the managed companion so existing extrude path still resolves through `profileRef`.
8. Add tests for shape lowering, draw return flow, review selection flow, snapping, and extrude compatibility.

## Acceptance Criteria

- entering `Draw` opens the floating viewer toolbar and closes/minimizes the spaghetti editor
- confirming `Draw` closes the toolbar and repopulates the `Draw` list in the editor
- `Line`, `Arc`, `Spline`, `Rectangle`, and `Circle` are all available first-pass tools
- `Rectangle` and `Circle` remain first-class in stored sketch state
- profile derivation lowers those shapes correctly for runtime/loop detection
- the `Close / Select Profile` row uses `Review`, not `+`
- `Review` enters profile-review mode and returns the selected profile summary to the editor
- exactly one valid detected profile auto-selects
- multiple valid detected profiles require explicit user choice
- sketch overlays render in ParaHook viewer code and do not rely on Replicad to display editable primitives
- current extrude flow still resolves through `profileRef`
