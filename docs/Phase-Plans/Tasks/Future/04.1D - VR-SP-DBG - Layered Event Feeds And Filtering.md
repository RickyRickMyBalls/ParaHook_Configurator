## Doc Body

### Summary

Extend the shipped console so it becomes a richer live event surface, not just a shell with a narrow command seam.

`4.1D` is locked as:
- expanding the visible layer set by exactly three new layers:
  - `View`
  - `Browser`
  - `Transforms`
- improving filtering beyond simple toggles with:
  - per-layer visibility
  - isolate mode
  - small multi-layer subset mode
- adding an optional diagnostics pin behavior
- expanding publisher coverage across the main app/viewer systems without turning the console into a full inspector

### Locked Outcome

`4.1D` should deliver:
- stronger publisher coverage from the main app systems into the transcript
- clearer ownership for which subsystem writes to which layer
- a filtering model stronger than the current on/off layer row
- a console that stays readable as feed volume grows

### Locked Layer Model

Keep the current shipped visible layers:

- `Commands`
- `Shortcuts`
- `App`
- `Worker`
- `Diagnostics`
- `Params`
- `Selection`

Add exactly these new visible layers in `4.1D`:

- `View`
- `Browser`
- `Transforms`

Defer:

- `Timeline`

Important rule:
- do not add more visible layers than these in `4.1D`
- new layers should exist only when they materially improve transcript scanability

### Locked Filtering Model

The `4.1D` filtering model is:

- keep the current per-layer on/off toggles
- add isolate-one-layer mode
- add small chosen-subset visibility mode
- do not add transcript text search in `4.1D`
- filtering only changes visibility
- filtering never deletes transcript history

The console should support:

- normal mode
  - visible layers behave as regular on/off toggles

- isolate mode
  - one chosen layer becomes the primary visible layer set

- subset mode
  - a small selected group of layers stays visible together

### Locked Diagnostics Behavior

Diagnostics behavior in `4.1D` is:

- diagnostics follow normal filtering by default
- diagnostics can be optionally pinned visible
- if pinned, diagnostics remain visible while other layers are isolated or muted
- diagnostics are not permanently always-on

Important rule:
- diagnostics pin is optional visibility behavior, not a second transcript or separate inspector surface

### Locked Publisher Expansion Targets

The first publisher expansion targets in `4.1D` are:

#### `Browser`

- row selection changes
- visibility toggles
- import events
- retry events
- remove events
- graph open / focus / close actions

#### `View`

- frame actions
- zoom actions
- camera lock or object-focus notes
- view-mode changes where they matter

#### `Transforms`

- start
- cancel
- commit
- mode switches
- axis constraints
- snap toggles
- snap value changes

#### Existing Layers That Stay Aligned

Keep these publishers aligned and coherent instead of reinventing them:

- `App`
- `Worker`
- `Diagnostics`
- `Params`
- `Selection`

### Feed Quality Rules

Every new or expanded publisher in `4.1D` must follow these rules:

- entries must be short
- entries must be chronological
- entries must belong to one intentional layer
- avoid per-frame or per-render spam
- prefer state-change events over continuous status repetition
- warnings and errors must remain visually distinct from ordinary notes

Important rule:
- if a system would naturally publish many repeated updates, publish only meaningful state transitions instead

### Important Interfaces / Behavior To Lock

- layer set after `4.1D`:
  - existing shipped layers plus:
    - `View`
    - `Browser`
    - `Transforms`
- filtering behavior:
  - normal per-layer toggle visibility
  - isolate-one-layer mode
  - chosen-subset mode
  - optional diagnostics pin
- publisher rule:
  - features publish state-change events, not high-frequency spam
- transcript rule:
  - filtering never destroys stored entries

### First-Pass Integration Shape

`4.1D` should extend the already-shipped console shell, window modes, and command-input work rather than rebuilding them.

The implementation should stay centered around:

- the existing `src/app/console/` store and shell components

- the current layer toolbar and console tools area

### Locked Deferrals

Keep these out of `4.1D`:

- command parsing/routing work from `4.1C`

- text search

- the new `View`, `Browser`, and `Transforms` layers are visible and toggleable

  - row selection changes
