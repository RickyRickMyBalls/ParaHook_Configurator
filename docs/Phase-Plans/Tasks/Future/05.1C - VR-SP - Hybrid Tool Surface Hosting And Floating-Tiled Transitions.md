## Doc Body

### Summary

`5.1C` defines what can live inside the hybrid workspace and how tool surfaces move through it.

This phase should lock:
- the first hosted-surface set
- pane header responsibility
- surface instance identity and clone policy
- windowed/tiled transition rules
- the first startup arrangement

### Locked Outcome

At the end of `5.1C`, the hybrid workspace should have one clear first-pass hosting contract:
- which surfaces participate
- how they enter tiled mode
- how they return to floating mode
- how pane headers and title bars expose those actions
- how multiple instances are represented honestly

### Locked First Eligible Surface Set

The first hybrid surface set should be:
- `Model Viewer`
- `Browser`
- `Console`
- `Gizmo/View`
- `Spaghetti Editor`

Important rule:
- these are the first honest hosted surfaces
- smaller secondary panels can follow later once the shared hosting model is stable

### Locked Pane Header Responsibilities

Pane headers should own:
- current surface label
- surface switching
- `Float This Surface`
- pane-local close/merge actions

Standalone floating title bars should own:
- first split entry from `Windowed` state

Divider lines should own:
- deeper layout authoring

### Locked Clone-Capable Hosting Rule

All eligible surfaces should be architecturally clone-capable.

Important rule:
- do not hard-lock the shared workspace to singleton-only surfaces

The system should explicitly support:
- `Move Existing`
- `Clone Surface`

Default UX can still begin simple, but the architecture must preserve both meanings.

### Locked Surface Instance Identity Rule

Every hosted surface instance should have its own instance identity.

The hosting model should separate:
- surface kind
- surface instance id
- placement mode
- instance-local UI state
- shared feature state where appropriate

Important rule:
- cloning a surface is not the same thing as cloning the underlying project/content data

### Locked Tiled And Windowed Transition Rules

Every eligible surface should support:
- `Tile This Surface`
- `Float This Surface`

Rules:
- floating should preserve the last floating rect
- tiling should preserve last tile placement when possible
- dragging a tiled surface back into the model viewport should return it to `Windowed`
- if the user drags `Browser` into the model viewport, it should still behave like the current floating-in-viewport Browser instead of being forced back into a tiled-only presentation

### Locked Special Surface Rules

`Console`:
- title-bar right-click should allow:
  - `Split Horizontal`
  - `Split Vertical`
- if `Console` is already split, it should also allow:
  - `Combine Back To Model Viewport`
- `Combine Back To Model Viewport` should:
  - remove the split pane hosting `Console`
  - restore `Console` to its docked floating form over the main model viewport

`Spaghetti Editor`:
- title-bar right-click should allow:
  - `Split Horizontal`
  - `Split Vertical`
- choosing one should create the requested split and move that editor into the new tiled pane

General standalone floating surfaces:
- right-clicking the title bar while `Windowed` should create the first split against the current model viewport region

`Browser`:
- dragging `Browser` into the model viewport should preserve the current floating shell behavior it already has today
- this is an explicit first-pass hybrid rule, not legacy fallback behavior

### Locked Default Hybrid Arrangement

The first default hybrid arrangement should start with:
- tiled `Browser`
- tiled `Console`
- tiled `Gizmo/View`

Rules:
- the existing left-dock `[]` split button remains the clean first entry into that state
- `Spaghetti Editor` can be tiled/docked into the layout later by the user
- the arrangement should help the user start immediately without forcing every tool into tiles on day one

### Important Interfaces And Types To Lock

- `WorkspaceSurfaceInstanceId`
  - stable id for one hosted surface instance
- `WorkspaceSurfaceHostPolicy`
  - move existing
  - clone new
- `WorkspaceSurfaceTransitionAction`
  - tile
  - float
  - split horizontal
  - split vertical
  - combine back to model viewport
- `CombineBackToModelViewport`
  - explicit contract for:
    - deleting the current split pane
    - restoring docked floating presentation
