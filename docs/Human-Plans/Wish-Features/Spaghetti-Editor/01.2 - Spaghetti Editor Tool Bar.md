# 3 - Spaghetti Editor Tool Bar

## Doc History
1. 2026-03-06 02:26: Added local doc history block
2. 2026-03-06 02:26: Preserved the existing Spaghetti editor toolbar cleanup and redesign notes

Purpose:

This doc is for the future cleanup and redesign of the Spaghetti Editor toolbar area.

Right now the toolbar/header/canvas split is messy.

This doc should define what belongs in the Spaghetti Editor toolbar and what should move out of the canvas area.

It is not a task file yet.
It is a feature-direction doc.

## Current Problem

The Spaghetti Editor currently has controls spread across multiple places:

- `SpaghettiPanel`
  - help section
  - sample/load buttons
  - compile/build buttons
  - compile status and diagnostics summary
- `SpaghettiEditor`
  - expanded/collapsed editor controls
  - type legend
  - focus node
  - add part node
- `SpaghettiCanvas`
  - delete selected edge
  - tangent flip buttons
  - wire curve control
  - canvas message

This makes the toolbar feel fragmented.

The long-term goal should be:

The Spaghetti Editor toolbar becomes one intentional tool area.

## Main Goals

### 1. Update "How To Use Spaghetti Editor"

Current state:
- placeholder
- too rough
- not yet a clean real help/instruction panel

Future goal:
- rewrite it so it actually teaches the tool
- shorter
- clearer
- more structured

Possible direction:
- quick-start section
- controls reference
- wiring tips
- build/compile explanation

This should feel like a real tool help block, not temporary filler text.

## 2. Replace or redesign the sample/load buttons

Current buttons:
- Load Baseplate
- Load Baseplate - ToeHook
- Load Baseplate - HeelKick
- Load Cycle

Current issue:
- feels temporary/dev-oriented
- naming is not polished
- probably not the long-term user-facing tool model

Future goal:
- redesign how starter/sample graphs are loaded
- make this section feel intentional

Possible directions:
- Presets dropdown
- Starter Templates menu
- Sample Graphs section
- recent/open/create pattern

This should probably stop feeling like debug/dev buttons.

## 3. Info window is too tall / too much space

Current issue:
- the header/info/help area takes too much vertical space
- this makes the toolbar feel heavy
- it competes with canvas space

Future goal:
- shrink the info area
- tighten spacing
- reduce wasted vertical height
- make the toolbar/header more compact

This likely relates to:
- help content layout
- header section grouping
- scroll ownership
- spacing and min-heights

## 4. Drag bar button needs to be below the toolbar

Current intent:
- the drag bar is for manually collapsing/resizing the toolbar region
- the header button is for collapsing the whole header block

Desired behavior:
- the drag bar should sit directly below the toolbar region
- it should visually represent:
  - "toolbar above"
  - "canvas below"

This is different from the header toggle button.

The toolbar drag bar should control manual toolbar height.
The header toggle button should control the section being collapsed/opened.

That distinction should be visually and behaviorally obvious.

## 5. Move all canvas toolbar stuff into the main toolbar

Current canvas toolbar items:
- Delete Selected Edge
- Flip Tangent Side 1
- Flip Tangent Side 2
- Wire Curve slider
- canvas message

Current issue:
- these controls live inside the canvas surface
- they feel like a second toolbar
- the toolbar experience is split in two

Future goal:
- move canvas toolbar tools into the main Spaghetti Editor toolbar area
- reduce canvas-owned controls that are not truly canvas-only

Possible future structure:

### Main Toolbar Sections

- Help / Info
- Sample / Template loading
- Compile / Build
- Editor controls
  - Expanded / Collapsed
  - Focus node
  - Add part node
- Canvas tools
  - Delete selected edge
  - Flip tangent side 1
  - Flip tangent side 2
  - Wire curve slider
- Message / status area

This would make the canvas itself cleaner and make the toolbar feel like one real tool surface.

## Recommended Direction

The Spaghetti Editor should eventually have one clear toolbar system with:

- compact help/info
- sample/template controls
- build controls
- editor controls
- canvas tools
- status/messages

The canvas should become the working surface, not a place where extra toolbar controls live.

## Related Current Files

Current toolbar/header/canvas split is spread across:

- `src/app/panels/SpaghettiPanel.tsx`
- `src/app/spaghetti/ui/SpaghettiEditor.tsx`
- `src/app/spaghetti/canvas/SpaghettiCanvas.tsx`

Any serious cleanup here will likely touch all three.

## Summary

This future feature is about turning the Spaghetti Editor toolbar into one coherent tool surface.

The main desired changes are:

- rewrite the "How To Use Spaghetti Editor" section
- redesign the sample/load controls
- make the info/header area shorter
- place the toolbar drag bar directly below the toolbar
- move canvas toolbar controls into the main toolbar

Right now the controls are split across too many places.
This doc exists to define the direction before implementation starts.
