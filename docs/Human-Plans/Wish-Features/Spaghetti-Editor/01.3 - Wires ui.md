# 01.3 - Wires UI

## Purpose

This doc describes a future `Wires UI` feature for the Spaghetti Editor.

The main idea is:
- when the user builds or compiles, active wires should briefly light up
- those wires should show direction of flow toward `OutputPreview`
- the user should also be able to turn this path visualization on persistently with a toolbar toggle

This is intended to help users understand:
- what is active
- what is feeding preview
- how information is flowing through the graph

## Core Idea

There are two related behaviors.

### 1. Build / Compile Pulse

When the user builds or compiles:
- active wires briefly animate
- active nodes can also highlight
- the effect shows flow from source toward `OutputPreview`

This is a one-shot event.

### 2. Render Path Toggle

There should also be a persistent toolbar toggle:
- `Render Path`

When enabled:
- active render-path wires stay highlighted
- active flow stays visible continuously

This gives the user a way to inspect the graph without needing to trigger a build every time.

## Desired Visual Behavior

The active path should:
- highlight the wires that contribute to `OutputPreview`
- show direction of movement from source to destination
- make it obvious which path is currently relevant for preview

The intended direction is:
- source node -> downstream nodes -> `OutputPreview`

## Visual Direction Options

Possible flow visuals:

- moving dashed stroke
- arrowhead marker at the end of the wire
- repeating `>` / `>>`-style directional motion

Recommended current approach:
- moving dashed stroke
- plus an arrow marker

That gives a strong "flow" feeling without inventing a heavy custom rendering system.

## Scope Of Active Wires

Only active graph paths that contribute to `OutputPreview` should get this treatment.

That means:
- not every wire in the graph
- not every connected node
- only the path that actually contributes to preview output

## Architecture Rule

This should be a pure UI overlay driven by derived state.

It must not:
- mutate graph topology
- add hidden graph edits
- change compile behavior
- change worker behavior

It should be computed from existing graph and preview state.

## Source Of Truth

The active path should be derived from existing preview/graph state.

Likely source:
- `selectPreviewRenderVm`
- or a companion selector built beside it

The selector should be able to derive:
- `activeNodeIds`
- `activeEdgeKeys`
- optionally active preview slots

These should be computed from:
- `OutputPreview` slot connections
- upstream graph traversal
- diagnostics / validation state

## Suggested Derived State

Useful selector outputs:

- `activeNodeIds: Set<string>`
- `activeEdgeKeys: Set<string>`
- `activeSlotIds: string[]`
- optionally:
  - `unresolvedActiveEdgeKeys`
  - `activeRenderablePathOnly`

## Unresolved / Invalid Edges

If an edge is unresolved or non-ok:
- it should not be treated the same as a successful active render path

Possible handling:
- exclude it from the active renderable path
- or style it differently if it is still relevant diagnostically

Important rule:
- keep the result deterministic
- keep the styling readable

## UI State

This needs UI-only state, not graph state.

Suggested UI state:
- `renderPathEnabled: boolean`
- `compilePulseNonce: number`
- `compilePulseUntilMs: number`

Purpose:
- `renderPathEnabled` controls persistent render-path mode
- `compilePulseNonce` or `compilePulseUntilMs` controls the one-shot pulse

## Trigger Rules

Suggested behavior:

- on build or compile:
  - trigger pulse for about `800ms`
- render overlay when:
  - `renderPathEnabled === true`
  - or pulse is still active

This keeps the feature lightweight and UI-only.

## Toolbar

The Spaghetti toolbar should eventually include:
- `Render Path`

Behavior:
- toggle on/off
- UI-only
- no graph mutation

## Rendering Layer

The wires UI should be applied inside the canvas wire rendering layer.

When a wire is in the active render path:
- increase emphasis
- animate dash movement
- show direction marker

When a wire is not active:
- render normally

## Combined Styling With Diagnostics

Diagnostic styles already exist for some invalid or non-ok wires.

This feature should not destroy that readability.

If a wire is both:
- diagnostically important
- and part of the active path

Then the styles should combine in a readable way rather than fight each other.

## Suggested Implementation Shape

### Selector Layer

Add or extend a selector to compute:
- active nodes
- active edges
- render-path state

### UI State Layer

Add UI-only state for:
- persistent render-path toggle
- build pulse timing

### Toolbar Layer

Add:
- `Render Path` toggle

### Canvas Layer

Apply active styles to matching wires:
- thicker stroke
- glow or emphasis
- animated dashes
- arrow marker

### Test Layer

Add deterministic tests for:
- active path selector output
- repeated selector stability

## Suggested First Version

A good first version would be:

1. derive active path from `OutputPreview`
2. add persistent `Render Path` toggle
3. add one-shot pulse on compile/build
4. render active wire emphasis
5. add directional animation

This gets the feature useful quickly without overbuilding it.

## Open Questions

- Should only currently visible `OutputPreview` slots count?
- Should active nodes highlight too, or only wires?
- Should inactive wires dim when render path is enabled?
- Should pulse happen on compile click, build finish, or both?
- Should unresolved active paths be shown as warnings or ignored?

## Short Version

This feature is a read-only graph-flow overlay for the Spaghetti Editor.

It should:
- highlight the active path to `OutputPreview`
- show direction of movement
- pulse on build/compile
- optionally stay on with a toolbar toggle

And it should do all of that:
- without mutating the graph
- without changing compile behavior
- using selector-driven derived state only
