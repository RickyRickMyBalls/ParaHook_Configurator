## Doc Body

### Summary

`Model-Viewport-1` should be the umbrella geometry-overhaul roadmap for the `Model Viewport` family, not the detailed implementation home for every child subphase.

Current read:
- the repo currently has a fast mesh-first graph-native runtime
- that runtime is useful for preview speed, but it is not yet the authoritative long-range geometry truth
- the new vision direction now wants:
  - one shared geometry request contract
  - one shared geometry result contract
  - a fast draft preview path for interactive edits
  - a slower authoritative geometry path that can later support B-rep-capable outputs and clean `.step` export
- the viewport needs explicit honesty about which result class the user is seeing:
  - `draft`
  - `authoritative`
  - stale/loading/failure states around those results
- the viewport also needs a real user-facing preview policy:
  - `Auto`
  - `Draft`
  - `Final`
- the current dead top-left three-state viewport control is the cleanest first home for that mode family

Locked recommendation:
- keep this file as the parent roadmap only
- do not reuse this file as the detailed implementation source for each child once `1.1`, `1.2`, or `1.3` gets its own dedicated future doc
- keep the viewport as the display and policy surface, not the hidden owner of geometry semantics
- make preview policy a real execution policy, not only a visual hide/show toggle
- prefer `Auto / Draft / Final` over the vaguer `Auto / On / Off`

## [ ] Model-Viewport 1.2 - Draft Preview Execution And Viewport Swap Rules

### Summary

#### Purpose:
- make the viewport honest about draft versus authoritative geometry during interactive edits
- define preview policy as real build/execution behavior

#### Current read:
- the current repo already has a fast mesh-first path that is a plausible draft-preview base
- what is still missing is the viewport-owned display policy around when that draft should run and when it should be replaced
- this child should make sure the user can disable preview work when it slows the authoritative path down

#### Locked direction:
- support a real preview policy:
  - `Auto`
  - `Draft`
  - `Final`
- use the current dead top-left three-state viewport control as the first home for that mode family
- `Auto` means:
  - draft preview follows Browser `live / release / off` policy
  - authoritative/final work still targets release by default for normal viewport-facing execution
  - show draft preview immediately when available and swap to authoritative geometry when it becomes ready
- `Draft` means:
  - target draft-preview execution only
  - Browser `live / release / off` policy applies here
  - show only preview geometry
  - do not replace the viewport with authoritative geometry while this mode stays active
- `Final` means:
  - show only authoritative geometry
  - skip draft execution work instead of merely hiding draft visuals
  - still use release as the normal final-execution trigger instead of running authoritative work live on every intermediate edit
- the viewport should show:
  - draft when available and allowed
  - stale/loading states honestly while authoritative geometry is pending
  - authoritative geometry when it arrives

### Questions / Decisions

#### [ ] Question 1 - What should the viewport show while authoritative geometry is still building?

##### Must lock
- keep stale geometry or replace it
- loading-state language
- failure-state fallback

#### [ ] Question 2 - What exactly should `Auto / Draft / Final` mean at display time and execution time?

##### Must lock
- that Browser `live / release / off` policy belongs only to draft preview execution
- that `Auto` may show draft first while ordinary authoritative/final work still defaults to release
- whether `Draft` also suppresses final replacement while active
- whether `Final` skips draft generation entirely while still keeping release as the normal authoritative trigger
- whether this mode is viewport-local, workspace-local, or later project-local policy
