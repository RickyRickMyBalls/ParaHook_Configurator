### Family Phase Goal

`Catalog-Gen2-6` should finish Generation 2 by adding only the metadata groundwork that current Gen2 data can truthfully support.

The output should help later Generation 3 work understand:
- which items are parts versus starting assemblies
- which source fields are known, unknown, or deferred
- which future builder or compatibility systems may need slot, sub-assembly, or dependency metadata
- which Gen2 HLG/CLG are complete, incomplete, or explicitly deferred

This phase should not invent compatibility truth. If the current Catalog data does not know whether a motor, tire, controller box, rear box, battery, BMS, or fastener combination actually works, this phase should say so instead of producing a false pass/fail read.

### Boundary Rules

- Store metadata only where current Gen2 item truth supports it.
- Prefer optional, sparse fields over fake defaults.
- Preserve source truth and unknown states.
- Do not add live builder behavior, slot validation, compatibility verdicts, or dimensional checks.
- Do not create fake repo-backed source records to satisfy builder slots.
- Do not use external PubParts records as proof that a local model is available.
- Do not widen Import-owned STEP behavior.
- If a wishlist item cannot be honestly completed in Gen2, record the owner and follow-up route instead of checking it off silently.
