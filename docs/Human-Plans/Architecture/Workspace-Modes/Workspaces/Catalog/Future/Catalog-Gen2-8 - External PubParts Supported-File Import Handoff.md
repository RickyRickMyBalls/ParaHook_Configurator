## Doc Body

### Family Phase Goal

`Catalog-Gen2-8` should let the user stage or download source files from an external PubParts entry, inspect what was staged, choose supported files, and then import selected files without lying about ownership.

The lifecycle should stay explicit:
- `external source entry`
- `staged/downloaded source`
- `imported project asset`

The action should read as source download, source inspection, or import handoff, not normal repo-backed `Add To Project`.

Healthy wording examples:
- `Download Source`
- `Inspect Files`
- `Import From Source`
- `Choose Files To Import`

The import path should stay staged:
- the user starts the action
- Catalog stages or downloads the source into the PubParts downloads area
- Catalog inspects the linked source, archive, or direct file candidate
- ParaHook classifies supported, unsupported, reference, and unknown files
- the user chooses which supported file or files to import
- selected files hand off to the normal import/project pipeline with source attribution

Phase 1 owns the first dedicated browser-storage bucket for PubParts download staging. The bucket should read as a local storage folder named `Catalog/PubParts/Downloads` on Home Page, even before actual download records exist, so the user can see where later PubParts source downloads will be staged.

### Boundary Rules

- Preserve the existing external-linked PubParts card/page/source identity.
- Display the PubParts downloads staging bucket on Home Page as storage ownership, not as proof that files have been downloaded.
- Keep external source entries, staged/downloaded source files, inspected source files, importable supported files, and imported project assets as separate states.
- Show downloaded-versus-imported status before any action treats a file as project-owned truth.
- Clearing staged PubParts source state must not delete imported project assets or attribution history.
- Keep source-page opening separate from source/archive inspection.
- Do not inspect, download, extract, or import source contents until the user explicitly starts the action.
- Do not expose repo-backed `Add To Project` for an external item before a supported file has been selected and imported.
- Direct file links may classify from clear URL/file metadata.
- Folder or archive links should stay staged until contents are inspected.
- The first supported file candidates are `.step`, `.stp`, `.glb`, `.obj`, and `.stl` when the existing Import family can accept them.
- Unsupported and reference files should remain visible as source context rather than disappearing silently.
- Preserve PubParts provider, source page, linked archive URL, source freshness, and original item attribution on the selected-file handoff.
- If STEP loader fidelity becomes the blocker, route that exact blocker to the Import family instead of widening Catalog.
