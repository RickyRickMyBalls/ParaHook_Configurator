## Doc Body

### Generation Goal

Generation 2 should evaluate durable, single-user undo candidates that are valuable but less foundational than the completed Gen 1 graph, CAD/sketch, Browser/project, Import/Catalog, Viewer Transform, and derived-reader coverage.

The generation should not start by making every visible setting undoable. Each candidate must first prove:
- the state is durable authored project or user state
- the commit boundary is explicit
- undo/redo can restore only owned authored state
- preview, runtime, cache, provider, navigation, focus, menu, and session state remain excluded

### Current Routing

- `Future/Edit-History-Gen2-1 - Durable Scene Presentation Undo Candidates.md`
  - scene, material, environment, lighting, and display-preset candidates after ownership is explicit
- `Future/Edit-History-Gen2-2 - Productivity Content Undo Candidates.md`
  - notepad/dashboard text and durable board organization candidates after ownership and storage are explicit
- `Future/Edit-History-Gen2-3 - Workspace Layout And Preference Undo Candidates.md`
  - durable project/user layout and mode preference candidates after storage and commit semantics are explicit
- `Future/Edit-History-Gen2-4 - Sampler And Import Setting Undo Candidates.md`
  - committed sampler/import settings that affect durable authored output after staging/runtime exclusions are proven

### No-Widening Rule

Gen 2 setup does not implement runtime undo. It must not add source code, tests, schemas, storage, keyboard dispatch, history panel UI, persistence, collaboration, Gen 3 checkpoints/branching, Build Path comparison, or broad setting infrastructure. It only creates routing and future planning surfaces.

### Acceptance Read

Gen 2 planning setup is acceptable when the family has:
- one scan index for durable Gen 2 candidates
- one concise future doc per approved candidate area
- explicit ownership/storage questions for each candidate
- explicit no-widening rules that keep runtime/view/cache/provider/session state outside canonical undo
- discoverability from the family index, family vision, docs index, and doc log
