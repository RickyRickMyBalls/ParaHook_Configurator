# 01.2 - Browser Workspace

## Doc History
1. 2026-03-12 15:18: Created this focused Browser architecture doc from the shipped `SP - Phase 11`, `2.1A`, and `2.1B` state so the Browser workspace has its own current truth surface separate from the master Spaghetti overview

## Purpose

This doc explains the current Browser workspace architecture inside the Spaghetti system.

Use it to answer:
- what the Browser currently shows
- where Browser row truth comes from
- what Browser interaction state is local UI state
- how Browser selection relates to editor focus and the shared viewer
- what the Browser does not yet honestly own

This is a current-state architecture doc, not a future Browser wish doc.

## Scope

This doc covers:
- the current Browser tree structure
- graph-document rows
- published graph-output child rows
- viewport rows
- Browser-local selection and expansion state
- Browser row actions and coordination rules

This doc does not cover:
- the final project-content hierarchy
- materials, visibility, or reference controls
- Browser build bars
- full Browser-side composition authoring
- true multi-window graph editing

## What The Browser Is

The Browser is now a workspace shell above graph documents, project content, and editor viewport records.

It is no longer just:
- a flat graph list
- a graph launcher
- a side panel that silently proxies editor focus

It is now responsible for presenting a first-pass tree of:
- project content
- graph documents
- published graph outputs
- open viewport/session records

## Current Tree Structure

The current top-level Browser shape is:
- `Project`
  - `Content`
  - `Graph Documents`
  - `Open Viewports`

### Content

`Content` is the project-owned branch.

Current rule:
- this branch reads from `useAppStore`
- it is not the same truth source as graph rows or published graph-output rows

This branch is still relatively thin and should not be mistaken for the final Browser-facing content hierarchy.

### Graph Documents

`Graph Documents` is the first honest graph-authored Browser branch.

Each graph-document row:
- represents one graph document
- can expand/collapse
- shows saved/dirty state
- shows open/focused viewport state
- exposes graph actions through the row context menu

When expanded, a graph row shows one thin child level:
- published graph-output rows

### Open Viewports

`Open Viewports` shows current editor viewport/session records.

Each viewport row:
- points at a graph document
- shows focus or z-order meta
- exposes explicit `Focus` and `Close` actions

Important caution:
- this branch is about current viewport/session records in store
- it should not be read as proof that the shell already presents a full literal multi-window editor system

That shell-honesty cleanup is still a later follow-up.

## Current Row Types

The current shared Browser row model covers three row kinds:
- `graph-document`
- `published-output`
- `viewport`

### Graph-Document Rows

Graph rows currently carry:
- `rowId`
- `graphDocumentId`
- `cachedGraphId`
- label
- meta text
- selection state
- expand/collapse state
- read-only shared-viewer participation status
- row actions

Current graph-row actions:
- `Save`
- `Open`
- `Reveal`
- `New Editor`
- `Swap Editor`

### Published-Output Rows

Published-output rows are graph-owned child rows.

They currently carry:
- source `graphDocumentId`
- `outputEntryId`
- label
- publication meta
- publication state
- Browser-local selection state

Current publication states:
- `resolved`
- `unresolved`
- `empty`

Current published-output action:
- `Reveal`

Important rule:
- these are not yet project-owned `Component`, `Object`, or `Part` rows

### Viewport Rows

Viewport rows currently carry:
- `editorViewportId`
- `graphDocumentId`
- label
- focus/z-order meta
- Browser-local selection state
- row actions

Current viewport actions:
- `Focus`
- `Close`

## Truth Boundaries

The Browser is a mix of read models from different ownership layers.

### Graph And Published-Output Truth

Graph rows and published-output rows read from Spaghetti-owned state:
- `graphDocumentsById`
- cached graph lifecycle state
- graph runtime output surfaces
- editor viewport open/focus counts
- shared viewer composition status

Current main source:
- `useSpaghettiStore`

### Project Content Truth

Project content rows read from:
- `useAppStore`

Important rule:
- project content should stay separate from graph-owned publication truth

### Browser-Local UI State

The Browser owns some local UI state that is not durable product truth.

Current Browser-local state includes:
- selected Browser row id
- expanded graph-document ids
- context-menu state

Important rule:
- the Browser may own interaction context
- it does not own graph, project, or viewer truth

## Browser Interaction Model

### Selection

Single-clicking a Browser row:
- selects that Browser row locally
- does not automatically focus an editor viewport
- does not automatically change shared-viewer composition

This applies to:
- graph rows
- published-output rows
- viewport rows

### Explicit Editor Actions

Editor movement remains action-driven.

Current editor-moving actions are:
- graph row `Open`
- graph row `New Editor`
- graph row `Swap Editor`
- viewport row `Focus`

Important rule:
- Browser selection is not editor focus

### Reveal

`Reveal` is the current Browser-to-viewer action.

Current first-pass rule:
- reveal is graph-scoped

That means:
- graph-row `Reveal` points at that graph document
- published-output-row `Reveal` still points at its source graph document

Current implementation seam:
- `viewerTargetGraphDocumentId`

### Shared Composition Status

When shared viewer composition is active:
- graph rows may show read-only participation status
- reveal is disabled
- the Browser does not add/remove composition membership

Important rule:
- the Browser may show composition status
- it does not yet author composition membership

## Current Browser Anatomy

The Browser now uses one shared row shell for its main graph-focused row kinds.

Current anatomy is effectively:
- expand affordance
- type icon
- label
- meta/state text
- actions through context menu

Current icon labels:
- `G`
  - graph document
- `O`
  - published output
- `V`
  - viewport

Important rule:
- the hierarchy is primary
- row actions are secondary

## Current Browser Meaning By Section

### What `Graph Documents` Means

This section means:
- authored graph documents that exist in the project/workspace
- plus one thin graph-owned publication child level

It does not mean:
- final project content placement
- final output/content hierarchy

### What `Open Viewports` Means

This section currently means:
- viewport/session records known to the Spaghetti workspace state

It does not yet fully guarantee:
- a one-to-one literal visible multi-window shell the user can inspect in the app at all times

This is the current shell-honesty gap still called out for later cleanup.

## Current Limitations

The Browser intentionally stops short of several later systems.

It does not yet provide:
- deeper `Component / Assembly / Object / Part` hierarchy
- Browser-side build bars
- richer item controls like visibility/material/selectability
- final context-menu cleanup and naming polish
- Browser-authored shared-composition membership
- true multi-window editor ownership semantics

## Practical Mental Model

The safest current mental model is:

- `Content`
  - project-owned content surface
- `Graph Documents`
  - graph-owned authoring/publication surface
- `Open Viewports`
  - current editor viewport/session records
- Browser selection
  - local Browser state
- editor focus
  - viewport/workspace state
- viewer target
  - reveal/viewer state
- shared composition membership
  - explicit shared-viewer composition state

These are intentionally different layers.
